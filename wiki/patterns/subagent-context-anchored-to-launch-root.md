# 子代理上下文锚定会话启动目录（实验设计判例）

## 症状

四轮探针（2026-09-06）：把主目录的 CLAUDE.md/AGENTS.md/技能目录改名后，子代理仍收到全文注入；把会话切入一个没有任何治理文件的 detached worktree 后，子代理仍被注入主目录的 AGENTS.md、22 个 SP 技能列表与 MEMORY.md；会话根经 change_directory 实际迁到无治理目录后（迁移本身仅用户侧动作才落地），新派发子代理仍全量注入主目录治理。

## 根因

子代理的项目上下文（claudeMd、技能列表、项目记忆目录）解析自**会话启动时的项目根**，不随 cwd 切换、磁盘改名或会话根迁移更新。技能列表虽是每次派发时读盘，读的也是启动根的 `.claude/skills`。

## 处置

- 在既有会话内构造"无治理基线臂"不可能；A/B 设计时先跑注入探针验证边界。
- 需要纯净对照：headless `claude -p`（需 CLI 登录；桌面应用认证 token 不导出，且 token 不落 shell 环境）或由人在目标目录手动开新会话。
- 会话内退路：**指令级隔离**——任务提示词内显式要求忽略被注入的说明文件/技能/记忆并禁用 Skill 工具。属"被告知忽略"而非"从未见过"，残余影响不可完全排除，报告中须如实标注隔离级别。相关：[[session-root-move-disables-hooks]]
