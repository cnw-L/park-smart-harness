# 完整 AI 服务测评方案

> 用途：本项目 AI 服务的**完整评测体系**——架构师视角搭框架、工程师视角给落点。对齐 2026 行业做法 + 腾讯 V6 附录 A 验收指标 + 本项目（5 类工具 / ReAct+plan / 控制安全 / RAG / 数字人交互）。
> 定位：本文是**评测框架与方法论的龙头**；`01 测试方案` 作为"附录 A 逐条指标"的明细附录；`编排测试集/` 是可跑落点。
> 日期 2026-06-22。

---

## 0. 总览：评测不是"跑一遍测试"，是一个工程体系

三条铁律（行业共识）：
1. **离线先行，再上在线**：先建离线评测达基线、再测覆盖、再做指标-结果对齐，**最后**才加在线/持续评测。
2. **评测驱动开发（EDD）**：评测嵌进开发运维全周期，不是上线前补一次。
3. **用公认框架的公认指标，不自造**：RAG 用 **RAGAS** 的标准指标、agent 用 **tool correctness / task completion / trajectory**、RAG 检索引用 tau-bench 的 **state-based**。自造指标无法横向对标、面试也不认；只有引擎确定性逻辑(state/闸/降级)用自家 pytest 断言（那本就是单测、非"评测"）。

用两个轴定位任何一条评测：

```
          组件级(每模块)    端到端(任务/轨迹)    系统级(非功能)
离线(上线前) ┌─────────────┬──────────────────┬──────────────┐
            │ 意图/RAG/    │ 编排/任务完成/    │ 压测/         │  ← golden dataset + CI 门
            │ 工具调用单测 │ 轨迹/多轮/兜底    │ 并发/可用性   │
在线(上线后) ├─────────────┼──────────────────┼──────────────┤
            │ span 级在线  │ 会话级在线eval/   │ 延迟/成本/    │  ← 生产 trace + 监控 + 回流
            │ 评测(漂移)   │ A/B/满意度        │ 漂移告警      │
            └─────────────┴──────────────────┴──────────────┘
```

## 2. 三种判定方法（什么时候用哪种）

| 方法 | 适用 | 特点 | 本项目用在 |
|---|---|---|---|
| **规则/确定性** | 字段透传、工具序列、参数 | 可程序化、零波动 | 上下文传递率、工具序列 |
| **state-based（后端状态 diff）** | 有副作用/控制类 | **最准、无评分波动**、可精确扣分 | **控制链、越权、降级（优先用这个）** |
| **LLM-as-judge（G-Eval）** | 主观/语义：任务完成、回答质量、RAG 忠实度 | 有波动 → 多次取平均 + 人审校准 | 任务完成、RAG、回答质量 |
| **人工抽检** | 高风险/主观 | 校准 LLM judge | 安全关键、急救指引内容 |

> 关键约束（等保三级、不外接未授权大模型）：**LLM-as-judge 的判官模型必须跑本地混元/qwen**，对话数据不出域。

## 3. 离线评测（上线前 · CI 门）

**拆两套**（别混测）：

| 套 | 测什么 | 模型 | 频率 | 通过线 |
|---|---|---|---|---|
| **engine** | 引擎确定性逻辑（闸/降级/控制时序/状态） | 可控假模型(ScriptedModel) | 每次提交 | **100% 绿**（红=代码 bug） |
| **model** | 模型行为（选工具/编排/任务完成） | 真 qwen | nightly | 统计阈值（如 ≥90%），跑 3+ 次取平均 |

- **数据集**：甲方提供集（意图/幻觉/术语）+ 自建集（多轮/编排/注入/越权/降级），**版本化**，见 `01 §7`。
- **基线 + 回归**：每次跑不低于基线；阈值门卡 CI、低于线阻断部署。
- **engine 套** = pytest + 假模型 + 确定性 assert（state-based）；**model 套** = pytest + DeepEval（Tool Correctness / Task Completion / G-Eval）。

## 4. 在线评测（上线后 · 静态测试覆盖不了的）

- **全链路 trace**（Langfuse 自托管）：记录每个 span——检索/工具/子 agent handoff 的输入/输出/延迟/成本。
- **在线 evaluator**：对生产流量持续算 correctness / hallucination / latency。
- **漂移检测 + 人审校准**：检测分布漂移和真实世界新失败；对主观输出，**人工复审校准 LLM grader**（Anthropic 2026 评测指引明确：生产监控是静态测试替代不了的）。
- **badcase 回流闭环**：线上 badcase → 回流成离线评测集 → 补测 → 防再犯。
- **A/B + 1-click 满意度**：对应腾讯好评率≥80%、任务完成率统计。

## 5. 工具链选型（开源 + 自托管 + 本地判官）

| 用途 | 选(GitHub) | 理由 |
|---|---|---|
| 离线语义评测(pytest式+CI) | **DeepEval**(confident-ai/deepeval) | 像 pytest、Tool Correctness/Task Completion/G-Eval、原生 CI、判官可换本地 |
| RAG 评测 | **RAGAS**(explodinggradients/ragas) | RAG 标准四件套 + 检索/生成拆开（§5.1） |
| 轨迹/工具调用评测 | **agentevals**(langchain-ai/agentevals) | 现成 trajectory match(严格/LLM-judge),不用自己写轨迹断言 |
| 端到端多轮对话评测 | **agent-evaluation**(awslabs) | LLM evaluator 编排多轮对话测你的 agent + CI |
| trace+数据集+在线eval+回流 | **Langfuse(自托管)** | 管 trace/数据集、和 DeepEval/RAGAS 互通 |
| 压测 | **JMeter / Locust / k6** | 并发/延迟 |
| 方法论范本 | **tau2-bench**(sierra-research) | dual-control + state-based reward + voice + RAG,你系统的学术对照物 |
| 判官模型 | **本地混元 / qwen** | 等保：数据不出域 |

> **排除**纯 SaaS（LangSmith / Braintrust 云 / Confident 云）做数据与判官——对话数据不能外发；可用其开源客户端。

## 5.1 RAG 用 RAGAS 四件套（公认标准，别自造）

RAGAS 的核心理念:**把"检索失败"和"生成失败"拆开测**——混在一起是团队改不动 RAG 的头号原因。四个标准指标:

| RAGAS 指标 | 面 | 测什么 | 对应腾讯 |
|---|---|---|---|
| **Context Recall**（上下文召回） | 检索 | 检索到的内容是否覆盖了该答问题的所有相关点 | **召回率≥90%** |
| **Context Precision**（上下文精确） | 检索 | 相关 chunk 是否排在前面（top 命中） | 召回质量 |
| **Faithfulness**（忠实度） | 生成 | 回答是否只基于检索内容、没编 | **幻觉≤5%**、安全幻觉≤0.1% |
| **Answer Relevancy**（答案相关性） | 生成 | 回答是否切题 | 回答质量 |

- **可溯源**(腾讯硬指标)= 回答带引用 + Faithfulness 高;RAGAS 评 faithfulness 时就基于"答案能否归到检索片段",天然支撑溯源。
- RAGAS 还有 **Tool Call Accuracy / Agent Goal Accuracy** 两个 agent 指标,正好补 §1 的工具调用/任务完成。
- 判官用本地混元/qwen(RAGAS 支持自定义 LLM)。
- 把"召回≥90%/幻觉≤5%"从一句口号,落成 **Context Recall≥0.9 / Faithfulness≥0.95** 的可跑数字。

## 6. 落到本项目（5 类工具）

- **engine 套（state-based，已写）**：控制链 / 越权红线 / 降级，6 条用例 → 见 `编排测试集/`。
- **model 套（DeepEval）**：设备管理 / 运行管理 / 生活服务 / 知识检索 / 执行工具 的选择与编排，用 Tool Correctness + Task Completion。
- **RAG（RAGAS 四件套）**：知识检索域跑 Context Recall/Precision + Faithfulness/Answer Relevancy，检索与生成分开看（§5.1）。
- **压测分档**：纯文本 / 单工具 / 多工具编排 / 带语音(GPU)——GPU 路径并发上限远低于纯文本，单独记 GPU 占用。
- **语音**：Step 7 专项 corpus（识别率/首包/打断/误打断）。

## 7. 评测生命周期（EDD，嵌进里程碑）

```
建离线基线 → CI 门(engine 每提交 + model nightly) → 上线
   → 在线监控(trace+在线eval+漂移) → badcase 回流 → 补离线集 → 迭代
```
对齐腾讯里程碑：MS1 定评测基线 → MS2–4 各 Sprint 跑离线门 → UAT 跑在线 + 满意度 → 重大活动专题日报。

## 8. 一句话方法论

> **离线先行、两套拆分、用公认框架的公认指标(RAGAS 四件套 / Tool Correctness / Task Completion / Trajectory Match)、控制类用 state-based、主观用本地 LLM-judge、上线后 trace + 回流**——DeepEval + RAGAS + agentevals + Langfuse 串起来，全部自托管、判官本地、可横向对标，对齐腾讯附录 A。**不自造指标。**
