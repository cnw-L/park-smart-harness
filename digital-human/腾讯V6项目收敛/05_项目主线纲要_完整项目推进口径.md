## 1. 定位

智慧园区 AI 服务——一个面向真实园区运营的**多智能体动态编排中枢**：用户用自然语言（语音/文本）提出诉求，系统识别意图、编排多个子能力办成事，并对真实设备等不可逆操作守住安全边界。

- **指导主线**：腾讯总部园区 V6 需求的「五层架构 + AI 对话中枢」。**取其主线，不照搬全部场景**。
- **技术路线（自研，非照搬腾讯选型）**：递归 ReAct 编排（非条件 DAG）、自建 Agent 运行时（非依赖某平台）、数字人**交互**（语音，**不含数字形象**）。
- **规模口径**：面向园区物业运营的稳定可控服务——重**稳定、可治理、能兜底**，不以高并发大规模为卖点。

## 2. 项目主线（要确保的脊柱）

> 主线 = **一条端到端服务闭环** + **两条贯穿脊**。保住这三样，项目就立得住；其余是宽度，按需铺。

### 主闭环（端到端）

```
用户(语音/文本)
  → 意图识别 / 任务拆解
    → 服务编排(多子 Agent 串并/条件，递归 ReAct 动态推进)
      → 能力执行(读查=自动；控制=确认后下发)
        → 结果归一 / 校验
          → 回答(语音/文本) + 计划与进度可见
```

### 脊一 · 安全（不可逆控制的护城河）

读/控分叉 → 三道闸（可控性·权限·确认）→ 提议-执行分离 → 幂等键 + 读回对账 → 错误/越权动作归零。**这是项目的立身之本**，深度优先于宽度。

### 脊二 · 质量（让回答可信、系统可恢复）

上下文工程（分层组装/压缩/记忆）+ RAG 知识底座（混合召回/自纠正/可溯源/白名单兜底）+ 会话事务化（中断可恢复）+ 兜底降级（每能力有降级路径）+ 评测可观测（用例集/回流闭环）。

> **判据**：主线达成 = 这条闭环在真实场景里跑通，且两条脊在闭环每一步都生效。**不要求 8 个子 Agent 全铺、不要求形象、不要求全部非功能指标**——那些是宽度。

| **③ 子 Agent 能力层（MCP）** | 设施运行 / 事项 / 生活服务 / 知识 等超域；提议-执行控制；统一治理注册 | 框架已成型，业务域接入推进中 |

## 4. 主线之外的取舍（保主线即可，不 1:1）

明确**不照搬**腾讯的部分，省力气、不当缺口：

| 腾讯有 | 我们的取舍 | 理由 |
|---|---|---|
| 8 个子 Agent 全量 | **先保 1–2 个域端到端打穿**，其余按主线复制扩展 | 主线是闭环深度，不是域数量；「加一个域=填表+三适配器」 |
| 条件 DAG 编排引擎 | 用递归 ReAct + todo 列表 | 并行/串行/重试是循环动态，不需要静态图 |
| 首页数字人**形象** | **不做**（定位为数字人**交互/语音**） | 形象是视觉外壳，非服务主线；可选未来 |
| CMS / 商户 B 端 / 硬件终端 / 导引牌 | 不自建，主线只对接 | 外围系统，非中枢 |
| 全量非功能（5000 并发/等保/四语全覆盖） | 按园区物业实际规模与阶段达成 | 不以大规模为卖点 |
| 混元 API / 腾讯云产品族绑定 | 模型与存储选型自主、可切换 | 中枢与具体云产品解耦 |

## 5. 推进路线（沿主线，分期）

> 治理优先、主线先穿、宽度后铺。每期交付一个**能演示的完整闭环增量**。

1. **主线穿透**：选 1 个域（如设施/综合查询）把端到端闭环（语音/文本 → 编排 → 读查能力 → 回答）真实跑通。
2. **安全脊加固**：把不可逆控制闭环接真后端（含 deviceCtrl 幂等化），越权/误操作红线测试通过。
3. **质量脊补齐**：评测用例集 + 兜底降级体系上线，关键指标进回归。
4. **宽度扩展**：按「填表+三适配器」复制扩到更多业务域（食堂/通行/会议/活动…）。
5. **入口完善**：数字人交互（语音）管线落地，多端接入。
6. **按需补外围**：商业/导航域、SSO、部署双链路等，依目标场景取舍。

> 每一期都讲成「完整项目又向前推进了一段」，而不是「补了一个缺口」。
