## 1. 三铁律 + 五原则(地基,先记住)

**三铁律(行业共识)**
1. **离线先行,再上在线**:先离线达基线→测覆盖→指标对齐,**最后**才加在线/持续评测。
2. **评测驱动开发(EDD)**:评测嵌进开发运维全周期,不是上线前补一次。
3. **用公认框架的公认指标,不自造**:RAG=RAGAS 标准指标;Agent=Tool Correctness / Task Completion / Trajectory;控制=state-based。只有引擎确定性逻辑(state/闸/降级)用自家 pytest 断言(那是单测,非"评测")。

**五原则(贯穿)**
1. **基准独立于被测**:gold 来自文档/认证,**不来自被测对象**。
2. **先焊代码、再考模型**:先假模型焊引擎立基线,后真 qwen 考行为。
3. **outcome 优先的诊断栈**:先看完成→再看轨迹→再定位组件。
4. **生产回流为主、合成为辅**:合成只是上线前脚手架(实验室 vs 生产差约 37%)。
5. **判官本地、数据不出域**:LLM-judge 全跑本地混元/qwen(等保三级硬约束);判官不可靠→ensemble + 人校 + 全自托管走 OTel 不锁死。

## 2. 评测全景(两轴定位 + 12 维度)

任何一条评测用两个轴定位:

```
          组件级(每模块)    端到端(任务/轨迹)    系统级(非功能)
离线(上线前) ┌─────────────┬──────────────────┬──────────────┐
            │ 意图/RAG/    │ 编排/任务完成/    │ 压测/         │  ← golden 集 + CI 门
            │ 工具调用单测 │ 轨迹/多轮/兜底    │ 并发/可用性   │

            └─────────────┴──────────────────┴──────────────┘
```

## 3. 核心方法:假模型立基线 → 真模型 → 诊断栈

### 3.1 一条线

```
[0] 假模型(FakeModelCaller)焊引擎所有分支→全绿;并当"候选 gold 的认证器"
[1] 造测试集(上线前·合成):
     RAG  : 文档 → RAGAS TestsetGenerator(知识图谱+Persona×题型) → (问题+答案+参考片段) → critic筛+人审
     Agent: 工具集+目标 → 强模型出(问题+候选plan) → 假模型逐样本认证(跑+断言) → 筛+人审
            (结果由后端跑、不由强模型编;gold=认证过的;APIGen 三级验证思路)
[2] 离线评测(上线前·卡上线):engine 套(假模型,每提交,100%绿) + model 套(真qwen,诊断栈,nightly,统计阈值)
[3] 上线门:engine 全绿 + model 达线 + 安全集人审 → 上线
[4] 上线后:OTel 埋点 → 自托管 Langfuse(trace+在线eval+漂移);生产 badcase 回流补集
[5] 闭环:失败→归因(engine绿⇒非代码)→调四旋钮(系统提示/工具描述/超域组织/grounding)→重测;回流补集回[2]
```

### 3.2 假模型双用途(别混)

| 用途 | 目的 | 样本要求 |
|---|---|---|
| **A. 测引擎(engine 套)** | 验引擎分支(闸/降级/控制时序/状态) | **分支覆盖即可,不需全样本**(coverage 量化) |
| **B. 认证 gold(出题)** | 给每条候选 plan 贴"可达+正确"标签 | **逐样本跑** |

**铁律**:剧本里只放**模型的决定**(调哪个工具/给答案),**不放工具结果**——结果由引擎拿决定去跑真工具/Fake后端产生。把结果也写死=自说自话,等于没测。

**认证 = 执行 + 断言**:假模型按脚本跑(执行)+ 判"最终状态==目标"(断言)。
- **执行省不掉**:plan 的中间结果(device id / handle)只有跑才知道;到没到目标只有跑完才能判。
- **断言替代的是"存 gold 轨迹 + 逐步比对",不是执行**:断言法只存目标状态、跑完比目标。
- 合成 vs 程序化的真区别只在"被跑的 plan 哪来":LLM 猜的(发现对不对、要剔错)/ 人写已知解的(自检没写错)——**两者都"跑+断言"**。

### 3.3 诊断栈(outcome 优先)

```
outcome(DeepEval TaskCompletion / Agent Goal Accuracy)  ← 先看办成没
  → trajectory(agentevals superset)                      ← 路径合不合理
  → tool(DeepEval ToolCorrectness)                        ← 选对工具+参数
  → state(自写后端状态断言 / proxy-state)                 ← 副作用对不对(控制优先)
  → RAG(RAGAS 四件套)                                     ← 知识域专项
```
**credit assignment(定位坏在哪组件)是领域公认未解难题,别指望单分数**——靠诊断栈逐层缩小。

## 4. 四种判定方法(什么时候用哪种)

| 方法 | 适用 | 特点 | 用在 |
|---|---|---|---|
| **规则/确定性** | 字段透传、工具序列、参数 | 零波动 | 上下文传递率、工具序列 |
| **state-based(后端状态 diff)** | 有副作用/控制类 | 最准、无评分波动;**执行前也查一次**防"什么没做就过" | 控制链、越权、降级(优先) |
| **★proxy state-based(行业延伸·2026-06)** | 控制类**但无确定性后端/无读回端点** | LLM 从 trace(对话+工具调用+读回回显)**推断**最终状态,不查后端;比 trajectory 稳(接受等价路径) | **我们控制链的现实落点**(真后端缺操作日志查询端点时,先用它) |
| **LLM-as-judge(G-Eval)** | 主观/语义:任务完成、回答质量、忠实度 | 有波动→多次取平均+人审校准 | 任务完成、RAG、回答质量 |
| **人工抽检** | 高风险/主观 | 校准 LLM judge(地板线 5–10% 抽检) | 安全关键、急救指引 |

> **★proxy-state 的价值(本项目关键)**:`08/12` 原方案 state-based 要"全确定性后端",而我们真后端**没有控制操作日志的查询端点**(TOCTOU 缺口),控制评测一直卡在"查不到后端真实状态"。[arXiv 2602.16246] 的 proxy-state 用 LLM 从完整交互轨迹推断"空调到没到 24 度",**绕开后端查询依赖**——这条**我们自己就能闭环**,不必等后端给端点。诚实 caveat:对**可观测/确定性**状态有效,不透明/随机状态会漏(与我们"读回对账"的可观测前提一致)。
> 判官全本地 qwen/混元,数据不出域。

## 5. 各域落地(5 类工具 + RAG + 控制 + 语音)

### 5.1 离线两套(别混测)

| 套 | 测什么 | 模型 | 频率 | 通过线 | 代码落点 |
|---|---|---|---|---|---|
| **engine** | 引擎确定性逻辑(闸/降级/控制时序/状态) | 假模型(`FakeModelCaller`) | 每次提交 | **100% 绿**(红=代码 bug) | `编排测试集/test_engine.py`(已 16 绿) |
| **model** | 模型行为(选工具/编排/任务完成) | 真 qwen | nightly | 统计阈值(如 ≥90%),跑 3–5 次取平均 | 待写 runner(用户环境,沙箱无 qwen);现有 `tests/test_tool_routing_eval.py` = 临时 model 套,待归位 |

### 5.2 五类工具 → 评测映射

| 域 | 工具(repo) | engine 套 | model 套 |
|---|---|---|---|
| 设备管理 | `facility_agent`(子) | 消歧 0/1/N、控制必确认时序 | Tool Correctness + 编排 |
| 运行管理 | `record_query` + 主中枢编排各域 summary | state(查询无副作用) | 跨域态势编排(已知弱 qwen reach gap) |
| 生活服务 | `meeting/parking/restaurant_query` | — | Tool Correctness |
| 知识检索 | `knowledge_query` | — | RAGAS(§5.3) |
| 执行工具 | `propose_control` / `execute_proposal` | **控制红线**:越权 deny=0、确认一次、拒绝不执行、幂等 | proxy-state 判控制结果 |

### 5.3 RAG = 两条腿(输出 RAGAS + 输入抽取可观测)

**腿一:RAGAS 四件套(输出侧,公认标准,别自造)**——把"检索失败"和"生成失败"**拆开测**:

| 指标 | 面 | 测什么 | 腾讯 |
|---|---|---|---|
| **Context Recall** | 检索 | 是否覆盖该答问题的所有相关点 | 召回率≥90% |
| **Context Precision** | 检索 | 相关 chunk 是否排前面 | 召回质量 |
| **Faithfulness** | 生成 | 回答只基于检索、没编 | 幻觉≤5%、安全幻觉≤0.1% |
| **Answer Relevancy** | 生成 | 回答是否切题 | 回答质量 |

- 出题:RAGAS `TestsetGenerator`(文档→知识图谱→Persona×题型→合成 问题+答案+参考片段);多跳靠"建关系";**大半不用标准答案**(Faithfulness=答案vs检索;Relevancy=答案vs问题)。
- 落成可跑数字:召回≥90%→`Context Recall≥0.9`;幻觉≤5%→`Faithfulness≥0.95`。判官本地 qwen。

**腿二:抽取可观测(输入侧,RAGAS 看不见的盲区·行业延伸)**——RAGAS 评的是检索+生成,**评不了语料/chunk 抽取质量本身**。补:
- 入库表列语义抽取**降级率可观测**(已落地:`llm_structured_extractor.degradation_stats` + WARNING 日志 + prewarm 聚合)——失败回落启发式不再静默。
- 入库后看降级率;高→查 6008,**别让烂语料双盲喂进 RAGAS**(输入烂,输出指标也白测)。

### 5.4 控制安全(红线) + 语音

- 控制:engine 套(state-based,确定性)证越权=0/确认一次/幂等;model+真路径用 **proxy-state**(§4)判"真生效"。
- 语音(Step7):专项 corpus(识别率/首包≤1.5s/打断/误打断),GPU 路径并发单独压测。

## 7. 数据集 + 样本量 + CI 门

- **数据集来源**:甲方提供集(意图/幻觉/术语)+ 自建集(多轮/编排/注入/越权/降级),**版本化**(见 `01 §7`)。
- **样本量(行业延伸·2026)**:
  - engine 套追求**引擎分支全覆盖**(可量化 coverage,**不是输入全样本**)——16 条已覆盖完成/闸/控制/并行/失败/budget/中断。
  - model/RAG 套是**统计指标**:**聚合指标 ≥500 条才可信**;手搓 anchor 50–100 条打底,其余靠合成认证生成。**别拿 20 条的通过率当结论。**
- **CI 门**:engine 套每提交 100% 绿(红=阻断);model 套 golden 上 key metric 掉破阈值→block merge;多跑取置信区间分"真回归 vs 抖动"。
- **EDD 生命周期**:建离线基线 → CI 门(engine 每提交 + model nightly)→ 上线 → 在线监控 → badcase 回流 → 补离线集 → 迭代。对齐腾讯里程碑:MS1 定基线 → MS2–4 各 Sprint 跑离线门 → UAT 在线+满意度。

## 8. 上线门(卡板)

```
engine 全绿(确定性逻辑无 bug)
  + model 套达统计线(完成率/路由/编排 ≥ 阈值,≥500 样本)
  + RAG 达线(Context Recall≥0.9 / Faithfulness≥0.95)
  + 控制红线(越权=0 / proxy-state 真生效)
  + 安全集人审过
  → 上线
canary 自动门(行业延伸):Shadow→5%(错误率<2%、p99<8s)→25%(工具成功率>95%)→50%→100%;回滚<60s=repoint
```

## 9. 在线(上线后)

- **全链路 trace**:OTel GenAI 埋点 → 自托管 Langfuse(每 step/工具/检索/子 agent handoff 一个 span,输入/输出/延迟/成本)。我们已有审计日志 → 改成 OTel 吐出。
- **在线 evaluator**:100% 跑启发式 + 5–15% 采样跑 LLM-judge(本地);embedding 漂移检测。
- **人审校准**:地板线 5–10% 抽检,持续跟 judge agreement(0–5 量表一致性最高)。
- **badcase 回流闭环**:生产 trace 一键转回归用例(补 gold/断言/脱敏)→ 进回归集 → CI 重测。**生产回流 > 合成**(合成覆盖不到的崩法)。
- **A/B + 1-click 满意度**:对齐好评率≥80%、完成率统计。

## 10. 诚实标注(共识 / 前沿 / 经验值)

- **强共识**:离线先行;两套拆分;用公认指标不自造;RAGAS 拆检索/生成;state-based 控制优先;生产回流>合成;人审校准 judge 必须;判官本地。
- **前沿/未定稿**:OTel agent 约定未冻结;**proxy-state(2602.16246)是新方法**(我们当解后端缺端点用,自承对可观测状态有效);RAGAS 评不了语料可信度(故补抽取可观测);GEPA 效果因任务而异(但已超 MIPROv2)。
- **经验值非硬统计(引用前再核)**:实验室 vs 生产差~37%;聚合需~500 样本;平台开销 12–15%。
- **有争议**:轨迹 exact-match 太脆(已转 state/superset);多 agent 取舍(我们选 ReAct+plan,站得住)。
