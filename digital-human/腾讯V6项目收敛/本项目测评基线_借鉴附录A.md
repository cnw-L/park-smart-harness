# 本项目测评与能力基线 —— 借鉴腾讯 V6 需求附录A

> **定位**:**不是投标达标**(那套已弃)。腾讯 V6《需求说明书》附录A 的指标与测试标准只作**借鉴**——取与本项目(`smart_park_assistant` harness:内圈引擎 / 中圈上下文 / 工具治理 / RAG / 控制安全)**实际相关**的,借其阈值当**参考标尺**,**不强求 1:1**,按本项目实际(自研 harness、qwen、几十人起步、可向上扩)定**自己的可达基线**。
> **靶子来源**:`需求说明书.pdf` 附录A(64 条全量)——仅取相关子集。

> 日期 2026-06-24。

---

## 0. 三条取舍原则

1. **借鉴 ≠ 对标**:只纳入与 harness 实际能力相关的指标(中枢编排/RAG/控制安全/性能可用);**别人层不纳入**(C端UI/CMS/硬件/定位精度/各业务数据延迟——那是完整 V6 的其它层,非本项目)。
2. **阈值当参考、按实际定基线**:附录A 阈值是"行业级好标准",借作目标方向;本项目按自研栈与规模定**自己承诺得起的基线**,达不到的诚实标"参考目标 / 待提升"。
3. **落到实际**:每条 → 借鉴阈值 / **本项目现状(对真实代码)** / 怎么测 / 优先级。

## 2. 不纳入的(借鉴其"该有验收标准"的思路,但非本项目)

完整 V6 的其它层,本项目(AI 中枢 + RAG + 控制)不含,故**不设这些指标**:
- **C端UI**(TDesign 偏离/视觉一致性)· **CMS/B端**(排片/插播)· **硬件**(红外计数器/防护等级 IP55/65)· **导航定位精度**(室外≤3米/室内≤5米/楼层识别)· **各业务数据延迟**(食堂拥堵/停车同步/接驳 GPS/活动同步)· **数字人形象首帧渲染**(本项目定位语音交互、不做形象)。
- 这些里**纯 AI 能力的点**(如报事 AI 分类准确率、推荐命中、无障碍语音查询成功率)若将来子 Agent 接真后端,可纳入 model 套;**现阶段桩态不设数字**。

## 3. 落到本项目的测评建设序(借鉴方法论,按"杠杆×可自闭环")

> 替代之前的"投标达标"路线。每步用方法论的标准件,产出**本项目自己的**测评基线。

1. **M0 安全红线(零依赖,先)**:`编排测试集/test_engine.py`(16 绿)纳入 repo + CI → 越权=0/控制确认/降级 的**确定性绿证据**(C 类 P0)。
2. **M1 对话+RAG 质量(需 qwen)**:model 套(DeepEval/agentevals)出 路由/编排/多轮 + RAGAS 四件套出 召回/幻觉/拒答(A、B 类);判官本地。**出题/建集是大头,独立排期**。
3. **M2 监测(greenfield)**:按 `监测层设计` 上 OTel 三支柱 → 出 响应/可用 的实测(D 类),并支撑在线 eval/漂移/回流。
4. **M3 性能/兜底**:k6 压测分档(并发,GPU 单列)+ Step2 兜底落地(降级切换)。
5. **MCP 化 / 日志保留**:沿北极星推进(E 类)。

> **借鉴腾讯 V6 附录A 的指标与测试标准,落到本项目实际**:纳入与 harness 相关的**对话/RAG/控制安全/性能可用** ~20 条,借其阈值当参考、按自研实际定基线;**别人层不设指标**。**先用 engine 套把安全红线证成确定性绿(本项目最强、零依赖),再 model 套+RAGAS 出对话/RAG 质量,再上监测出性能可用。** 不对标投标、不吹数字,只把本项目的真实能力测明白、把短板标清楚。
