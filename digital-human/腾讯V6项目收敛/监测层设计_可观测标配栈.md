# 智慧园区 AI 服务 · 监测层(可观测)完整设计

> **范围**:**监测/可观测层**(traces/metrics/logs + 在线评测/告警)。业务功能组件另设计,本文不含。
> **依据**:2026 行业实践(OTel 已成 LLM 可观测底座)+ 本项目栈(harness 三环 / agent_runtime / RAG / 语音;PG/Redis/Milvus/vLLM;等保三级自托管)+ 腾讯 V6 附录A 非功能指标。
> 日期 2026-06-24。

---

## 0. 设计原则(五条,决定一切取舍)

1. **标配优先 + 标准接口**:监测组件**一律用业界标准件**(OTel/Collector/Langfuse/Prometheus/Grafana/Loki),组件间只用**标准协议(OTLP/PromQL)** 解耦 → 可替换、可集成、可交接、可被上层接。**绝不写私有/非标监测路径**(唯一会设天花板、retrofit 贵的错)。
2. **完整三支柱**:traces + metrics + logs 缺一不算完整(只埋 trace ≠ 可观测)。
3. **为规模设计、按当下供给**:拓扑按完整标准搭(Collector 居中、可演进到 gateway+HA);几十人先最小供给(单 Collector/直连),上规模只加容量、不改设计。
4. **等保:全栈自托管、数据不出域、判官本地**;监测数据含对话(PII)→ 监测本身也是治理对象(脱敏/保留期/访问控制)。
5. **复用已有接缝**:harness 的 `audited_store` 边界、Protocol 接缝(ModelCaller/Gate/ControlCapability/Backend/Retriever)就是天然 span/metric 落点;审计(`PgAuditLog`)与监测**互补不冲突**,各走各 sink。

## 1. 监测全景:三层 × 三支柱(2026 行业标准分层)

行业 2026 生产 AI 监测栈分三层:**基础设施 / LLM 遥测 / 质量评测**。叠到三支柱:

| 层 | Traces | Metrics | Logs | 标准件 |
|---|---|---|---|---|
| **③ 质量评测**(LLM 特有) | 给 span 挂在线 eval 分 | 在线 faithfulness/任务完成/漂移 | badcase 详情 | **Langfuse**(在线eval)+ DeepEval/RAGAS 判官(本地) |
| **② LLM 遥测** | model/tool/agent/RAG span(gen_ai.*) | TTFT/TPOT/token/成本/工具成功率 | 模型 I/O(脱敏) | **OTel + OpenInference** → **Langfuse** |
| **① 基础设施** | 服务调用 span | RED(速率/错误/时延)+ USE(资源)+ GPU 占用 | 系统日志 | **OTel** → **Prometheus/Grafana + Loki** |

> 关键:**质量评测层是 LLM 系统区别于普通服务监控的核心**——APM 只看延迟/错误,看不见"答得对不对、有没有变差"。这层接你的评测方法论(在线侧)。

## 2. 标准拓扑(Collector 居中,可演进)

```
 应用进程(harness / agent_runtime)
   ├─ OpenInference instrumentor  → 自动埋 qwen 调用(gen_ai.* span)
   └─ 手埋 OTel span             → harness 自定义边界(见 §3)
        │  OTLP(标准线协议)
        ▼
 ┌──────────────────────────────────────────────┐
 │  OTel Collector(适配中枢)                      │  ★换后端/采样/脱敏/路由全在这,应用零改
 │  receivers: otlp · processors: batch/脱敏/采样 │
 │  exporters: ↓ ↓ ↓                              │
 └──────────────────────────────────────────────┘
     │                  │                 │
     ▼                  ▼                 ▼
  Langfuse           Prometheus         Loki
 (LLM trace+         (metrics)          (logs)
  在线eval+              │
  prompt版本+成本)        ▼
                     Grafana(看板 + Alertmanager 告警)
```

**演进路径(为规模,按当下供给)**:
- **现在(几十人)**:应用 **直连 Langfuse**(OTLP),或 **单 Collector**;Prometheus/Loki/Langfuse 单机自托管。
- **上规模**:Collector 转 **agent(sidecar/daemonset)→ gateway(中心聚合)** 两层;gateway **≥2 实例 + LB**(去单点);需采样时 **tail-sampling 只在 gateway**(它要看到一条 trace 全部 span;用 `loadbalancingexporter` 按 trace_id 路由)。**这步不改应用、不改埋点,纯加容量。**

## 3. 埋点设计(落到本项目的接缝)

### 3.1 LLM 调用 → 自动埋点(别手写)
`OpenInference`/`OpenLLMetry` instrumentor 包 qwen 的 OpenAI-compatible 调用 → 每次自动出 `gen_ai.*` span(含 input/output_tokens、模型、延迟)。

### 3.2 harness 自定义边界 → 手埋 OTel span(instrumentor 不懂你的语义)
| span | 落点(代码) | 关键属性 |
|---|---|---|
| **会话/agent**(根,一次 run_loop=一条 trace) | `run_loop` 入口 / `audited_store` 边界 | `session.id=thread_id`、`gen_ai.agent.name`、principal(脱敏) |
| **iteration** | loop while 每轮 | 轮序、budget 余量、是否压缩 |
| **tool 执行** | `dispatch.execute_one` | `gen_ai.tool.name`、disposition(allow/ask/deny)、ok/error、超时/重试 |
| **gate 决策** | `CatalogGate.classify` | allow/ask/deny、capability、是否越权 |
| **RAG 检索** | `retrieve_evidence` | 召回条数、best_rerank_score、是否二轮、insufficient |
| **控制** | propose/execute | grounding 通过/拒(机器码)、是否真生效(读回)、幂等命中 |

> 复用接缝:这些点你**已经有 ok/error/disposition/score/usage_tokens 在手**,现在算完就扔;埋点 = 把它们 `set_attribute` 进 span。

### 3.3 命名约定(标配,不自造)
- LLM:**OTel GenAI 语义约定 `gen_ai.*`**(钉 `OTEL_SEMCONV_STABILITY_OPT_IN` 版本;未冻结,预期小幅变动)。
- 服务指标:**RED**(Rate/Errors/Duration)+ **USE**(资源)。
- 项目自定义维度:`thread_id`/`tool.disposition`/`control.effective`/`gate.denied`——**带分区键(tenant/thread),为多租户/分片预留**。

## 4. 监什么:指标清单 × 腾讯附录A 映射

四大类(行业共识)+ 直接对到附录A:

| 类 | 具体指标 | 标准件 | 腾讯附录A |
|---|---|---|---|
| **延迟** | **TTFT(首 token)** / TPOT / 端到端 / **Goodput**(同时满足所有 SLO 的 QPS) | Prometheus 直方图 | **首 token ≤2s**、语音播报≤1.5s |
| **用量/成本** | token(in/out)/ 请求数 / 每会话成本 / 模型分布 | OTel+Langfuse | 成本归因(并入网关侧) |
| **错误/可用** | 错误率 / 超时率 / 降级触发率 / **可用性(SLO)** | Prometheus+RED | **可用性 99.9%**、降级 100%/切换≤3s |
| **质量/安全** | 在线 faithfulness/任务完成/工具选择率 / **漂移** / **越权次数** / 注入命中 | Langfuse 在线eval(判官本地) | **召回≥90%/幻觉≤5%/越权=0/拒答≥90%**、好评≥80% |
| **资源(语音/GPU)** | GPU 占用 / 并发档(纯文本/单工具/多工具/语音) | Prometheus+DCGM | **并发 500/2000/5000 分档** |

> **GPU 路径并发上限远低于纯文本 → 单独记 GPU 占用、并发分档诚实标**(不混报一个并发数)。

## 5. SLO + 告警(burn-rate + quality-aware)

- **定 SLO**(对齐附录A):可用性 99.9%(月错误预算 ~43min)、TTFT p95 ≤2s、越权=0(硬)。
- **告警绑 SLO burn-rate**(非裸阈值)→ 降噪、抓持续劣化;告警**带上下文**(受影响 feature/模型版本/最近变更),发 Slack/企微。
- **★quality-aware 告警**(APM 抓不到的静默失败):**在线 eval 分跌破阈值 / 漂移 / 越权≠0 / 降级率骤升 → 告警**。这是 LLM 系统特有、最容易漏的一类。

---

## 6. 在线评测 + 漂移 + badcase 回流(接评测方法论的"在线侧")

- **采样策略**:100% 跑启发式(规则/正则,便宜)+ **5–15% 采样跑 LLM-judge(本地 qwen)**(贵,采样)。
- **漂移检测**:prompt/模型/用户行为变 → embedding 漂移 + 在线分分布漂移。
- **badcase 回流闭环**:生产 trace → **一键转回归用例**(补 gold/断言/**脱敏**)→ 进 `编排测试集` → CI 重测。**自建一个"trace→case"转换器**(别依赖 SaaS 一键)。
- **判官校准**:对 LLM-judge 的在线分,**地板 5–10% 人审抽检**、持续跟 agreement(0–5 量表一致性最高)——**否则在线数字不可信**。

---

## 7. 等保 / 安全(监测数据本身的治理)

- **全栈自托管**:Langfuse/Prometheus/Grafana/Loki/Collector 全部 VPC 内,**对话数据不出域**;判官本地 qwen。
- **PII 脱敏**:在 **Collector processor** 层做(span attribute 进库前脱敏)——一处治理、跨所有后端生效。
- **保留期 + 访问控制**:trace/日志设保留窗口 + 角色化访问(监测台也要 RBAC)。
- **监测是治理对象**:Collector/Langfuse 的接入同样 deny-first,别当可信内部(MCP/网关同理)。
- **审计 vs 监测互补**:`PgAuditLog`(合规留痕,写边界,**模型不可写**)继续走;OTel trace(可观测)并行,挂同一边界、各走各 sink。**别用 trace 替审计**(trace 可采样/会过期,审计要完整不可篡改)。

## 8. 扩展性(为规模设计、无天花板)

| 维度 | 现在(几十人) | 上规模 | 是否改设计 |
|---|---|---|---|
| Collector | 单实例/直连 | agent→gateway 两层 + LB + ≥2 HA | ❌ 只加容量 |
| 采样 | 不采(全量) | gateway tail-sampling(按 trace_id 路由) | ❌ 配置项 |
| 存储 | 单机 | Prometheus→Mimir/Thanos、Loki 分片、Langfuse 多副本 | ❌ 标准件横扩 |
| 上层接入 | — | 吐 OTLP + Prometheus 远程写,上层照标准收 | ❌ 标准协议 |

> **唯一会撞墙的**:写了非 OTLP 的私有监测路径。只要全程 OTLP + 标准件,扩容 = 加机器 + 改 Collector 配置。

## 9. 落地分期(完整设计 + 按当下供给)

| 期 | 做什么 | 依赖 | 产出 |
|---|---|---|---|
| **M0** | OTel SDK + OpenInference + harness 手埋 span;**ConsoleExporter** 本地验证 span 结构 | **零**(纯库) | span 树本地可见 |
| **M1** | 自托管 **Langfuse**(traces+在线eval+成本)+ **Prometheus/Grafana**(RED+TTFT SLO 看板) | 部署 Langfuse/Prom | 延迟/成本/trace + 看板 → 附录A 延迟数字 |
| **M2** | **Loki**(logs)+ **告警**(burn-rate + quality-aware)+ **badcase 回流**转换器 | M1 | 告警 + 回流闭环 |
| **M3** | Collector **agent→gateway + tail-sampling + HA**(**规模到了再上**) | 负载增长 | 高可用监测 |

## 10. 选型总表 + 诚实标注

| 角色 | 标准件(自托管/本地) | 备注 |
|---|---|---|
| 埋点标准 | **OpenTelemetry**(SDK + GenAI semconv) | 已成 LLM 可观测底座(OTLP 事实协议) |
| LLM 自动埋点 | **OpenInference / OpenLLMetry** | 包 LLM 调用,免手写 model span |
| 适配中枢 | **OTel Collector** | 换后端/采样/脱敏/路由全在此 |
| LLM trace+在线eval | **Langfuse**(自托管,可选 v4 OTel-native SDK) | prompt 版本/成本/在线 eval 最强 |
| 指标+看板+告警 | **Prometheus + Grafana + Alertmanager** | RED/USE/SLO 标准 |
| 日志 | **Loki / OpenSearch** | 结构化日志 |
| 判官 | 本地 qwen | 等保:不出域 |

**诚实标注**:① OTel GenAI agent 语义约定**未冻结**(钉版本、预期小变);② 平台开销实测 **~12–15%**(少数来源,宜自核);③ tail-sampling 有复杂度(gateway 需见全 trace,引入 loadbalancingexporter),**规模没到别提前上**;④ OTel **只给 trace,不算 eval 分**——质量层仍靠 DeepEval/RAGAS 判官(本地)。
