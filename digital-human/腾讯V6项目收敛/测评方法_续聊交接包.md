## 1. 五条贯穿原则(先记住)

1. **基准独立于被测**(gold 来自文档/认证,不来自被测对象)。
2. **先焊代码、再考模型**(先假模型、后真 qwen)。
3. **outcome 优先的诊断栈**(先看完成 → 再看轨迹 → 再定位组件)。
4. **生产回流为主、合成为辅**(合成只是上线前脚手架;实验室 vs 生产差约 37%)。
5. **判官不可靠**(有自我偏好/复现性危机)→ 全本地 + 人校 + ensemble;**全自托管、走 OTel 不锁死**。

## 2. 完整逻辑路径(一条线)

```
[0] 假模型(FakeModelCaller)焊引擎所有分支 → 全绿;并当"候选 gold 的认证器"
[1] 造测试集(上线前·合成):
     RAG  : 文档 → RAGAS TestsetGenerator → (问题+标准答案+参考片段) → critic筛+人审
     Agent: 工具集+目标 → 强模型出(问题+候选plan) → 假模型跑认证可达+state断言 → 筛+人审
            (结果由后端跑、不由强模型编;gold=认证过的)
[2] 离线评测(上线前·卡上线):
     engine 套:假模型,确定性,每提交,引擎分支 100% 绿(CI 硬卡)
     model 套:真 qwen,诊断栈——
        outcome(DeepEval TaskCompletion) → trajectory(agentevals superset) →
        tool(DeepEval ToolCorrectness) → state(自写断言) → RAG(RAGAS 四件套)
        多跑 3–5 次取平均,统计阈值;判官本地
[3] 上线门:engine 全绿 + model 达线 + 安全集人审 → 上线
[4] 上线后(在线):OTel 埋点 → 自托管 Langfuse(trace+在线eval+漂移);
                  生产 badcase 回流补集(主力 gold);定期重跑离线套 + A/B + 满意度
[5] 闭环:失败→归因(engine绿⇒非代码)→调四旋钮(系统提示/工具描述/超域组织/grounding)→重测;
          回流→补集→回[2];判官定期人校
```

## 4. 术语/概念词典(校正过)

- **假模型**:`FakeModelCaller(list[ModelTurn])`,按次序吐写死的"模型决定",顶替 qwen → 让运行确定。**只喂决定、不喂结果**(结果由引擎+后端跑出)。
- **gold / reference trajectory(基线)**:期望动作序列;**候选 gold 必须用假模型跑过认证(可达+正确)才算数**。
- **诊断栈**:outcome → trajectory → component,**outcome 优先**。
- **trajectory match**:`strict`(同序,太脆)/`unordered`/**`superset`(含主干+允许多走,推荐)**。
- **state-based**:不判文字/轨迹,**断言后端最终状态**(确定、无评分波动);控制/agent 优先。**死磕 gold 轨迹太脆(Anthropic 批评),多条路径可能都对 → 用状态断言更稳。**
- **RAGAS 四件套**:Context Recall/Precision(检索面)+ Faithfulness/Answer Relevancy(生成面);**拆开测检索 vs 生成**;**大半不用标准答案**(Faithfulness=答案 vs 检索内容;Relevancy=答案 vs 问题)。
- **RAGAS 出题机制**:文档→知识图谱(切节点+摘要+NER+embedding+**建关系**)→ Persona × 问题类型分布 → synthesizer 合成(问题+标准答案+参考片段);**多跳靠"建关系"**;题源是文档。
- **LLM-as-judge 风险**:自我偏好偏差、对 prompt 敏感、可被注入/reward-hack → ensemble + 人校。
- **OTel GenAI 语义约定**:`gen_ai.*` 的 agent/workflow/tool/model span + 延迟/token 指标;埋一次可换后端。
- **Langfuse**:开源可自托管的 LLM 可观测平台(trace+在线eval+数据集+看板);**不替你打分**(接 RAGAS/DeepEval),**不替你跑系统**。

## 4.5 假模型 · 认证 · 断言(多轮纠错后的定论 · 重要)

> 这一节是几轮反复纠错收敛出来的,**之前对话里有几处说法被推翻,以本节为准**。

1. **假模型有两个用途,别混**:
   - **用途A 测引擎(engine 套)**:验引擎分支 → **分支覆盖即可,不需全样本**。
   - **用途B 出题认证 gold**:给每条候选 plan 贴"可达+正确"标签 → **逐样本跑**。
   - 同一个工具,两个目的;只有 B 是逐样本。"不用全样本"只对 A 成立。
2. **认证 = 执行 + 断言**:假模型按脚本跑(执行)+ 判"最终状态==目标"(断言)。**断言是认证的"判分"那一步,不是认证的替代。**(✗ 旧说法"断言替代认证"作废)
3. **执行省不掉**:plan 的中间结果(device id / handle…)**只有跑才知道**;到没到目标**只有跑完才能判**。(✗ 旧说法"程序化/断言法不用跑、构造即对"作废)
4. **断言替代的是"存 gold 轨迹 + 逐步比对",不是"执行"**:断言法只存目标状态、跑完比目标即可;省的是"那条要认证的 gold 轨迹",不是执行。
5. **合成法 vs 程序化法,真区别只在"被跑的 plan 哪来"**:
   - 合成:LLM **猜**的 plan → 跑+断言是"**发现**对不对"(要剔错);
   - 程序化:人**写**的已知解 → 跑+断言是"**自检**没写错"。
   - **两者都"跑+断言" = 都是假模型认证**,只是 plan 来源与目的(发现 / 自检)不同。
6. **结论**:**agent 出题,假模型逐样本认证(跑+断言)基本免不了**;唯一变量 = plan 来源。这也兜回了"agent 评测,执行基本每条样本免不了"。

## 5. 已确认结论(防回头)

- RAG 与 Agent **流程同形**(出题→自己跑→打分);**真正差别只在"出题工具成熟度"**——RAG 有 RAGAS,Agent **无 turnkey**。
- **DeepEval/agentevals 只是评分器**,不出题、不跑你的 agent。
- RAGAS **不是一体机**:生成 + 打分两模块,**中间你自己跑 RAG**;打分是**多维 LLM-judge,非答案字面对比**。
- engine 套**追求引擎分支全覆盖**(可做到,coverage 量化),**不是输入全样本**。
- 超时降级测试**要等 Step2 兜底实现**(见 `09`)才能补进 engine 套。

## 6. 未决 / 缺口

1. **Agent 出题无 turnkey**:需自建最小骨架(对标 RAGAS 模块A)。流程 = 出题(plan 来源:LLM 猜 或 人写已知解)→ **假模型逐样本认证(跑+断言,见 §4.5)**→ 筛+人审 → 测试集。注:认证这步两种 plan 来源都要做。
2. **model 套 runner 未写**:真 qwen → 适配器(转 OpenAI 消息)→ agentevals+DeepEval+state 断言,判官本地。沙箱无 qwen 跑不了,需在你环境跑。
3. **Step2 兜底未落**:3s 超时 + fallback_policy(设计见 `09`,待你拍 3 个决策点)。
4. **Langfuse/OTel 按需上**:几十人规模,真要在线 eval/漂移/回流再接。
5. **credit assignment**(定位坏在哪组件)是领域公认未解难题,别指望单分数。
