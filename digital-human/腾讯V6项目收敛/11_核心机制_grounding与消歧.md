# 核心机制:grounding(实体解析)与候选消歧

> 用途:把 harness 两个核心机制固化——**候选消歧(选哪台)** 与 **grounding(选定后控什么、值对不对)**。每个给「你的做法(代码实证)+ 行业做法 + 对照」。

## 一、候选消歧(0/1/N)—— `device_status`

### 你的做法

按名/区域查后端拿到 0/1/N 候选,**关键在"响应怎么塑形",不靠代码自动选**:

| 候选数 | 处理 |
|---|---|
| **0** | 明确"未查到、后端正常、无此名" + **防空转**("别用相近名反复重试…如实回报无此设备,别臆断成故障") |
| **1** | **直达**:直接返回单台 |
| **N** | **摘要优先**:首行 `共X台 + 按类型计数 + 按状态计数`(可直接作答);明细仅列前 12 台;尾注"其余已计入计数,要控制请指定编号" |

两条红线 + 弱模型防御:
- **读控分叉**:查询可摘要作答;**控制必须收敛到唯一设备,绝不替用户选**(选错对象=不可逆误操作);
- **弱模型塑形**:摘要防 stall(40 台 1819 字会让 qwen 反复重查触 stall)、系统名≠类型不缩窄("空调"原样传、不擅缩成"空调机组")、0 命中防臆断。

### 行业做法(实体链接 / 澄清 / 槽位填充)

1. **实体链接 / grounding 到 catalog**:人话 mention → 规范实体(查字典/检索);
2. **候选检索 + 重排**:取候选、按上下文重排、给 top-N;
3. **置信阈值决策**:置信高→直达;低/多候选→澄清(= 你的 0/1/N 的务实版);
4. **澄清提问 + 槽位填充**:缺槽/歧义问用户补;**高风险动作必须 HITL 澄清确认**(= 你"控制绝不替选")。

### 对照

| | 内容 |
|---|---|
| 一致 | 模糊→澄清、唯一→直达、grounding 到权威表、高风险必澄清(读控分叉) |
| 你多做 | **弱模型响应塑形**(摘要防 stall/系统名不缩窄/0 命中防臆断)——行业论文少讲 |
| 行业更系统 | 显式 confidence score 驱动;候选 retrieval+rerank;专门 entity-linking 模型 |

## 二、grounding(意图→可执行)—— `ground_control`

### 你的做法

**铁律:LLM 只产意图,规则查权威字典(`sycPointParamType`)解析、不编 id/值。**

```
模型给 Intent(坐标从 device_status 抬来、param/value 人话)
  ① 坐标校验:缺坐标拒(no_point_type);deviceId 非数字拒(bad_device_id,不静默产残缺 payload)
  ② 门禁特判:开关门固定动作(开=2/关=1)→ 直建走 doorControl
  ③ 查权威字典(代码查,非模型):有 point_id→getListByPointId(带当前值+边界);退化→sycPointParamType
  ④ 匹配参数:人话"温度"→可控参数(is_ctrl 优先,避开只读"送风温度");不可控拒(not_controllable)
  ⑤ 校验值:枚举→必在可选状态(value_not_in_enum);数值→必在 [min,max](out_of_range)
  ⑥ 分可逆性:能解析出绝对写=状态型=可逆;非状态型(denylist)=不可逆
  ⑦ ★硬依赖:不可逆 + 后端无幂等键 → 当场拒(irreversible_no_idem),降级人工
  → 产出 Grounded(完整 payload,deviceId 转 int)或 Rejection(带机器码)
```

**核心防线**:模型全程只说人话,真实 id/值由代码对字典校 → **模型再幻觉/听错,也推不动非法控制**(编不出错 id、写不进越界值、控不了只读参数、不可逆无幂等直接拒)。

**真机细节(读回对账+抓包挖出)**:门禁"多发字段假 200 不注册"→ door_payload 绝不多发;deviceCtrl 控门是假成功 → 门禁分流 doorControl;模拟量 paramStatus 也要填目标值(否则 param_exception)。

### 行业做法(结构化校验 / 约束生成 / 参数 grounding)

核心原则一致——**"LLM 提议、代码校验",不信模型的结构化输出**:
- **Schema / 参数校验**:模型出的参数对 **JSON Schema / API spec / 字典** 校验,不合规则拒/重问;
- **约束生成(constrained decoding)**:让模型只能输出 schema 内的合法值(枚举/类型);
- **参数 grounding**:把人话值解析/规范化为后端要的精确值(单位、枚举、范围);
- **deny-first 闸控**:高风险动作前权限 + 可逆性 gating(= 你的三道闸①)。

### 对照

| | 内容 |
|---|---|
| 一致 | "模型提议、代码校验"、参数对字典/schema 校、越界/不可控拒、高风险 gating |
| 你多做 | **可逆性分级 + 不可逆无幂等当场拒**(行业很少做到这层安全粒度);真机抓包级 payload 细节 |
| 行业更系统 | 约束生成(constrained decoding)从源头限制非法输出;标准 JSON Schema 校验工具链 |

## 三、两段衔接(消歧 → grounding)

```
device_status:0 澄清 / 1 直达 / N 摘要→用户指定唯一设备     ← 选哪台(消歧)
        ↓ 唯一设备坐标
ground_control:校验 可控/值在范围/可逆性 → 可执行动作或拒    ← 这台上控什么、值对不对
```
**读控分叉贯穿两段**:查可自动摘要;控必唯一对象 + 值校验 + 不可逆拒。

## 四、可测 + 缺口

- **可测**:消歧准确率、**控制误选率=0**(N 候选绝不替选)、0 命中防 stall;grounding 的越界/越权/不可控**当场拒=100%**、不可逆无幂等拒。
- **缺口**:真后端 gateway(facility 叶子现为桩);reversibility_map 上线前要把已知非状态型登全;门禁/扣费等非状态型接入前必须先补 denylist。

> **一句话:消歧解决"哪台"(响应塑形 + 读控分叉 + 阈值澄清,= 行业实体链接/澄清);grounding 解决"控什么、值对不对"(模型只产意图、代码查字典校验、不可逆无幂等拒,= 行业"模型提议代码校验" + 你额外的可逆性安全粒度)。**
