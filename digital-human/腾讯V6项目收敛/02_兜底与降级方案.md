# 兜底与降级方案

> 用途：研究收敛。把散落在腾讯需求（4.8 离线降级 / 6.2 降级策略 / 各子 Agent 降级行 / 2.2.2 异常降级）和你两套资料里的兜底机制，**整合成一张可验收的降级体系**。
> 兜底是腾讯的硬指标：`降级覆盖率 100%`、`切换≤3s`、`降级时主动告知用户`、`重大活动零事故`。当前两套资料里兜底是「点状提及」，没成体系——本文补齐。
> 配套：[`00_项目总纲`](00_项目总纲_全量架构与能力地图.md) · [`01_测试方案`](01_测试方案_验收指标对齐.md)

---

## 0. 兜底的总框架（四个层级，从轻到重）

```
L1 能力级降级   单个子 Agent / MCP 工具失败 → 重试→跳过→降级路径（每个 ≥1 条）
L2 链路级降级   AI 引擎不可用 → 降级到传统快捷入口 / 静态内容
L3 系统级降级   本地不可用 / 全网不可用（腾讯 4.8 三场景）
L4 安全级兜底   紧急链路独立 + 幻觉白名单 + 控制对账（不可降级的底线）
```

**总原则**（腾讯 6.2 + harness 治理）：
1. **降级必须主动告知用户**（腾讯硬性），不能静默降级让用户以为正常。
2. **紧急/安全链路不参与降级**——它本身就是最低降级态，独立于 AI 主流程，7×24（见 §4）。
3. **预算耗尽 = 如实降级停报，不自扩**（harness 治理纪律：预算不可自扩）。
4. **切换 ≤3s**——所有降级路径的切换耗时是验收项（附录 A）。

## 1. L1 能力级降级 · 每个子 Agent 的降级路径（腾讯 2.2.4 表内已给）

腾讯每个子 Agent 都给了降级方案,整理成统一表（**降级路径覆盖率必须 100%**）：

| 子 Agent | 正常态 | 降级态（腾讯已定） | 切换触发 |
|---|---|---|---|
| 食堂餐饮 | 实时热力图/预测 | 餐厅大屏实时排队展示（静态化） | 传感器/AI 超时 |
| 通行出行 | 实时车位/到站预测 | 静态时刻表 / 原停车 App / 原停车界面 | 停车 API 不可用→提示+跳转，≤3s |
| 商业服务 | 商户/活动/场馆动态 | 商户静态目录 / 原预约界面 | 商家平台/场馆后台超时 |
| 导航服务 | 室内外一体化导航 | **离线静态园区地图 + 文字指引 + 无障碍关键点列表** | 腾讯地图不可用，≤3s |
| 报事紧急 | AI 分类派单 | 7000 工单热线 / 紧急联系电话列表 | AI 不可用（紧急链路另算，§4） |
| 活动服务 | 在线报名/同步 | 活动公告页 + 人工报名 | 活动平台超时 |
| 综合查询 | 动态设施状态 | 设施目录静态页面 | IoT 超时 |
| 会议服务 | 会议室状态/控制 | OA 会议室预约界面 | 会议系统超时 |

**关联资产**：harness 的工具组织层已有 `fallback_policy`（manifest 字段，`park-ai-service-design.md §三`）——每个能力 manifest 必须填降级路径，**未填 fallback_policy 的能力不允许注册上线**。这是把腾讯降级表落进 harness 的具体动作。

**降级时延实现**：单次调度超时 ≤3s 触发降级（腾讯 2.2.2）。harness 工具治理层的 `timeout/重试/失败降级` 配置承载，后台可配（2.2.6 Agent 管理：超时/重试/降级可配 + 灰度回滚）。

## 2. L2 链路级降级 · AI 引擎不可用

| 场景 | 降级策略 | 用户告知 |
|---|---|---|
| AI 对话引擎挂 | 降级到**传统快捷入口**（按钮式菜单：导航/食堂/停车/报事直达原系统） | 「智能助手暂时不可用，已切换到快捷服务」 |
| 单个大模型 API 超时 | 重试→切备用模型 API（混元主 + 甲方批准备用） | 透明，不告知 |
| 语音管线挂（ASR/TTS） | 降级到纯文字交互（键盘输入 + 文字展示） | 「语音暂不可用，可文字输入」 |
| （定位外）数字形象 | 本项目定位为**数字人交互、无数字形象**，故无形象渲染降级一档；若未来接入形象，则降级链为 形象+语音 → 纯语音 → 纯文字 | — |

**关键洞察（按当前定位修正）**：本项目定位为**数字人交互、无数字形象**——所以「纯语音」就是**默认态**，语音挂了直接降级到纯文字。无形象渲染这一档不存在。若未来接入形象，再把降级链扩成 形象+语音 → 纯语音 → 纯文字。

## 3. L3 系统级降级 · 腾讯 4.8 三场景（逐字落地）

| 场景 | 腾讯策略 | 落地要点 |
|---|---|---|
| 场景一：单点系统不可用 | 切备份系统或降级服务；AI 引擎不可用→传统快捷入口 | = L1+L2，热备切换 ≤30s（6.2） |
| 场景二：本地不可用 | 小程序云端调度正常；大屏切预录视频；导览终端播缓存内容 | 终端要有**本地缓存内容** + 断网离线运行（6.1 弱网） |
| 场景三：全网不可用 | 大屏播预录视频；小程序不可用→现场人工引导 | 户外设备断网离线运行，网络恢复自动同步（4.7） |

**网络层兜底**（4.7）：云端+本地双活网关，网络中断时本地独立运行；重大活动主备双链路，切换 ≤10s。

## 4. L4 安全级兜底 · 不可降级的底线

### 4.1 紧急链路 7×24 独立（报事紧急子 Agent 的红线）

腾讯硬性：**紧急功能独立链路，不依赖 AI 引擎主流程；AI 不可用时紧急功能仍可用；7×24 可用性 100%**。

```
紧急 SOS / AED / 疏散
  ├─ 不经过 AI 引擎主流程（避免 AI 故障连累）
  ├─ 本地缓存关键信息：AED 位置、急救号码、最近安全出口
  ├─ 一键呼叫安保/医疗/消防 + 自动位置上报（≤3s）
  └─ 全降级态：紧急联系电话列表 + 静态 AED 地图 + 7000 热线
```

**实现要点**：紧急链路是独立服务，与 harness 主循环物理隔离；急救指引内容由甲方医疗/红十字会校验（不能让 AI 生成急救步骤——直接走白名单内容）。

### 4.2 幻觉白名单兜底（安全关键信息）

腾讯：安全关键信息（紧急电话/AED/医疗/消防）**基于白名单知识库兜底**，安全关键幻觉率 ≤0.1%，超出知识库拒答率 ≥90%。

- harness 三道护栏的**输出闸**：安全关键类问题→强制走白名单知识库，不走自由生成。
- RAG 强制带引用、可溯源（4.6）；知识库缺失→白名单兜底或拒答，绝不编造。
- 对应测试见 `01 §1`（≥50 条陷阱题）。

### 4.3 控制对账兜底（设备控制不可逆）

- **下发→读回→对账**（harness `总纲 §六`）：不信 deviceCtrl 裸布尔，读回 status 对照字典确认。
- 不可观测动作 → **降级给人**（三分表第③类）。
- 预算耗尽 → 如实停报，不自扩。

## 6. 降级验收与告知（统一规范）

**测试**（对应 `01`）：逐一关闭每个子 Agent / 每条链路，验证：
1. 降级路径生效（覆盖率 100%）；
2. 切换耗时 ≤3s（L1/L2）、热备 ≤30s（系统级）、双链路 ≤10s（重大活动）；
3. **降级时有主动告知用户的文案**（不可静默）。

**告知文案原则**：说清「降级了什么 + 还能用什么」，例：「实时排队暂不可用，已切换到食堂大屏数据」。避免只报错不给出路。

## 7. 收敛动作清单

1. **每个能力 manifest 填 `fallback_policy`**——未填不许注册（把 §1 表落进 harness）。
2. **紧急链路独立建设**——物理隔离于 harness 主循环，本地缓存 AED/急救号（§4.1）。
3. ~~形象降级链~~ — 本项目定位无数字形象，纯语音即默认态；形象降级链仅未来接入形象时适用（§2）。
4. **白名单输出闸**——安全关键类强制走白名单（§4.2）。
5. **降级告知文案库**——每条降级路径配一句用户文案（§6）。
6. **降级测试用例**——逐一关闭验证，进 `tests/e2e/`（见 `01 §0` L3）。
