# 园区数字人落地方案(纯语音,无形象)

> 目标:给 smart_park_assistant 现有"大脑"(LLM+RAG+上下文+记忆)套一层实时语音外壳,做出可用的园区语音数字人。
> 形象(Avatar)**明确砍掉** → 纯语音 → WebSocket 足够,不碰 WebRTC/MuseTalk(文档 §7.3 / §13.4)。
> 施工图依据:理论文档 §16.1 落地路线,按"纯语音 + 已有资产"重排。
> 研究方法:gap 驱动——只为缺的外壳件读 OAC,提取模式→定移植方案。详见 [研究主线.md](研究主线.md)。

---

## 核心认知:不是从零搭

```
园区数字人 = 已有"大脑" + 新建"实时语音外壳"
                ↑                    ↑
      smart_park_assistant      本方案要建的部分
      (LLM+RAG+上下文+记忆+ASR+TTS)   (VAD切句/聚合/清洗/打断/状态机/WS流式)
```
OAC 把 LLM 当可插拔 handler(openai_compatible/dify)→ 你的大脑就接在这个插槽。

---

## 目标架构(纯语音单 WebSocket)

```
浏览器前端(新建)
  getUserMedia(16k/单声道/AEC=on/noiseSuppression=off/AGC=off)  ← 抄 OAC track_constraints
  AudioWorklet 采集 → 16k PCM
  WebSocket(单条) ── 上行音频 / 下行音频 / 控制信号(独立队列)
  Web Audio 排期播放(nextPlayTime 游标 + playingSources 列表)   ← 参照 DH_live 前端
        ↕ WebSocket
后端编排层(新建,落在 demo_server)
  ┌─ 上行: SileroVAD 切句(+POST_END 重连) → ASR(已有 6011 流式 + 6012 整句)
  ├─ 决策: 轮次检测/误打断(语义路线)→ SEMANTIC_WAIT / INTERRUPT
  ├─ 大脑: LLM + RAG + 上下文 + 记忆(已有 smart_park_assistant)
  ├─ 下行: 句子聚合 + 文本清洗 → TTS(已有 CosyVoice2 6014)→ 流式回传
  └─ 状态: 显式 FSM(IDLE/LISTENING/THINKING/SPEAKING),不学 OAC dataflow
```

## 三类清单

### A. 已有,直接用(smart_park_assistant)
- 上行 ASR 双模型 6011(Paraformer 流式 partial)+ 6012(SenseVoice 整句 final)——**比 OAC 更教科书 2pass**,见 [[asr-voice-pipeline]]。
- 大脑:LLM + RAG + 上下文子系统 + 记忆/历史,见 [[context-subsystem-design-state]] [[rag-improvement-blueprint]]。
- TTS:CosyVoice2 6014(首包流式),见 [[cosyvoice-tts-deployment]]。

### B. 抄 OAC(提取模式/可直接移植)
- **句子聚合**:`token_buffer.py` 的 `SentenceAwareTokenBuffer`(标点+字数兜底200)→ 可整文件拿走。
- **VAD 切句**:`vad_handler_silero.py` 4 状态机 + **POST_END 重连**(解决停顿腰斩)→ 移植逻辑,参数单位是采样点@16k。
- **单 WS 双工**:`ws_input_delegate.py` 每通道独立 asyncio 队列 + 独立发送协程(信号不被音频堵)→ 这是纯 WS 复刻双工的蓝本。
- **误打断/轮次检测**:SemanticTurnDetector 的级联过滤(启发式停止词表 fast path → LLM)+ 附和词语义处理 + `avatar_was_speaking` 门控。
- **前端采集配置**:`track_constraints` noiseSuppression=off / AGC=off / AEC=on(与你 [[asr-voice-pipeline]] 踩坑结论一致)。

### C. 新建(OAC 没有或不适用)
- **文本清洗层(P0)**:LLM→TTS 去 markdown/emoji/符号,数字规范化。❌ 连 OAC 都缺,否则 CosyVoice 念"星号星号"(文档 §18.3)。放在句子聚合那一步一起做。
- **编排状态机**:显式 FSM(起步),不学 OAC 的 dataflow(那是为多模态+形象的复杂度准备的,你纯语音用 FSM 更可控好调试)。
- **WebSocket 流式 endpoint**:在 demo_server 加,承载上下行音频 + 控制信号。
- **前端**:采集 + WS + 排期播放(参照 DH_live `dialog_realtime.js`)。

## 施工阶段(文档 §16.1 落地路线,适配纯语音+已有资产)

> 原 §16.1 是"先跑 OAC 预置 config 再替换";你已有大脑+ASR+TTS,改为"自底向上拼外壳"。

**阶段 0 · 分诊(先做,文档 §16.3)**
- 实时采集音频存 wav 离线喂 SenseVoice,确认采集/格式没问题再往下(避免在错的层调参)。

**阶段 1 · 最小语音闭环(半双工,无打断)**
- 前端采集(16k/AEC/关降噪)→ WS → VAD 切句 → 已有 ASR → 已有 LLM/RAG → 句子聚合+文本清洗 → 已有 TTS → WS → 排期播放。
- 验收:能完整一问一答,首字延迟可接受。状态机先 IDLE/LISTENING/THINKING/SPEAKING 四态。

**阶段 2 · 下行提速(首包延迟,文档 §4/§19)**
- 句子聚合"第一个标点就送 TTS";文本清洗稳定;测端到端延迟 p50/p90,砍大头(VAD 静音阈值 + LLM 首 token)。

**阶段 3 · 打断(单 WS 逻辑优先级,文档 §5)**
- 控制信号独立队列(抄 OAC);前端 VAD 先行本地停播 + 清排期队列;后端 cancel(起步可不做 stream 图,直接 cancel 当前 LLM/TTS task + 标记丢弃)。
- 起步半双工降级:SPEAKING 时提高 VAD 阈值。

**阶段 4 · 误打断治理 + 轮次检测(语义路线,文档 §9/§3.2)**
- SemanticTurnDetector 思路:停止词表 fast path + LLM 判完成/打断/意图;附和词过滤;SEMANTIC_WAIT 延长等待防腰斩。
- 决策/执行解耦(像 OAC 的 InterruptHandler)。

**阶段 5 · 调优(文档 §10/§17/§19)**
- VAD 先调静音时长 + 加 padding;配业务热词表(权重 60-80,零成本);ITN 按场景测;延迟预算复盘。

- ✅ 状态机走显式 FSM(不学 OAC dataflow)。
