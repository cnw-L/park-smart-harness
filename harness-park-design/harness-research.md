# Harness：从局限到治理

> **一句话总纲**：Harness 是由模型局限反向决定形状、从痛中趋同演化而来、以"赋能 / 治理"两层为骨、以"读 / 写权威之缝"为生成判据、并因"服务任务还是服务人"而取舍分野的——一套把概率模型转化为受控能动体的工程理论；其赋能层随模型变强而消失，治理层随模型变强而加重，而治理的尽头——谁持笔——已不是工程问题，是制度问题。

本文是一份关于 agent harness（agent 运行时）的理论研究，不局限于任何单一实现。它回答四个递进的问题：harness **是什么**、**为何必然是这形状**、**会演化成什么**、以及在真实世界里**是否站得住**。

# 总一 · 立论

## 0.1 核心主张

模型本身只是一台"给文本、续写文本"的概率机。它被动、无状态、不可靠、且有限而昂贵。把这样一台机器放进真实环境去完成多步、跨轮、有后果的任务，外部必须有一整套工程系统替它维护状态、驱动推进、把守边界、兜住意外——这套系统就是 **harness**。

本文的中心主张分三层：

1. **harness 的形状不是设计选择，是被模型的局限反向决定的。** 把局限列全，部件就会自动浮现。
2. **harness 只有两种本质不同的部件**：一类是**赋能**（让模型*能*把事做成），一类是**治理**（让模型行使能动性时*可问责、有边界*）。劈开两者的，是一条判据——**模型可读、但能否拥有写权威**。
3. **这两层的命运相反**：赋能层随模型变强而被吸收、消失；治理层随模型变强而加重、不可侵蚀。harness 不会消失，它会**翻转**。

一句话压缩：**harness 一只手给出能动性，一只手扣住权威。** 智能不等于能动性；能动性是 harness 赋予的。

## 0.2 两张全景图

全文有两个视觉锚点，分别管"时间演化"和"当下定位"，正交互补（完整图见附录）：

- **翻转图**（赋能↔治理 × 模型能力）：随模型变强，赋能层这道楔形收窄，治理层这道带子增厚，两者之间那条上行的斜线就是"读/写权威之缝"。
- **二维定位图**（服务任务↔服务人 × 可逆↔不可逆）：把真实 harness 钉在平面上——Claude Code 在左上、Hermes Agent 在右上、智慧园区助手在左下。

# 分 · 主体

## 层 A：是什么 / 为何是这形状

### M1 · 本体论：harness 是什么

**定义**：Harness 是包裹在大语言模型外部的工程系统，它把"一个只能续写文本的概率模型"转化为"能在真实环境中完成多步任务、且行为受控的 agent"。

这个定义指向模型的两个根本局限，各逼出 harness 的一面：

- **被动且无状态**：给一段文本，续写一段就停；不记历史、无目标、不自发。要完成多步任务，外部必须替它维护状态、一轮轮驱动、把记忆喂回。→ 逼出 harness 的**驱动面**。
- **不可靠且不受约束**：会幻觉、会被诱导、会格式错乱、会调危险操作、会死循环。要放进真实环境，外部必须把关、限流、隔离、兜底。→ 逼出 harness 的**约束面**。

在一次完整执行中，模型只在"被调用、产出这一轮思考与动作"的一瞬出现，其余全是 harness：组装输入、解析输出、执行动作、维护状态、把守安全、决定是否继续。一个心智模型：**模型是大脑，harness 是神经系统 + 躯体 + 免疫系统**。大脑提供智能，但没有躯体它无法行动、没有神经系统它无法感知与记忆、没有免疫系统它无法在危险环境中存活。

> **第三根局限的补遗**：除"被动无状态"与"不可靠"外，模型还**有限且昂贵**（上下文窗口有限、单价非零）。后文会看到，这第三根局限不另立门户——它最终凝结为治理层里的"预算"对象（一个你读得见、却改不了上限的东西）。

### M2 · 发生学：harness 如何从痛中长出

理解 harness 的最佳方式不是看它最终的样子，而是看它如何从最朴素的起点被一系列具体的痛逐步逼出。起点：模型只会"给文本、续写文本"。试图让它做成一件多步的事，会接连撞上八个痛，每个痛逼出一个部件：

1. 续写完就停 → 把结果喂回去再续写 → **来回**
2. 不知要几轮 → 一个会判断何时停的循环 → **主循环**
3. 文本无法精确表达"调什么、传什么参数" → **结构化 tool_call**
4. 工具描述/参数/逻辑散落 → **Tool + 注册表**
5. 历史无限增长终将超窗 → **上下文分层与压缩**
6. 模型可能冲动或被诱导地执行危险动作 → **权限闸 + 人在回路**
7. 工具过多致选择退化、子任务污染主线 → **子 Agent 隔离**
8. 真实环境充满意外（坏输出、超时、限流、死循环）→ **错误恢复（重试/降级/兜底/预算）**

这个发生学视角揭示三个理论要点：

- **部件的必然性（条件版）**：每个部件不是被"设计"出来的，是被痛"逼"出来的。但必然性是**相对于任务复杂度**的——任务越复杂，越多部件从"可选"变为"必需"。不能说"每个都绝对必然"，但能说"任何想完成足够复杂多步任务的系统，都会独立长出这套部件的粗骨架"。这解释了不同团队的 harness 在结构上为何高度相似（趋同演化）。
- **简单性优先**：部件都是"最小够用"——主循环是个 while，动作是个结构化对象，权限是个三态判断。复杂性是在简单内核上按需叠加的。这呼应"让脚手架保持愚蠢、把智能留给模型"。
- **递归自相似**：第 7 个痛长出的"子 Agent"，本身又是一个完整的 harness（有自己的循环、工具、上下文、预算）。**多 Agent 系统不是新东西，是同一个 harness 的递归套叠**——理解一个 harness，就理解了整个多层系统。

> **〔线 B 伏笔〕** 趋同演化只在"粗骨架"层成立。再往细看，不同 harness 在**取舍**上严重分野——分野的根源留到 M7。

## 层 B：怎么组织 / 怎么运转

### M3 · 解剖学：被一把刀重切的结构

把八个部件按职责重组，传统上得到"一引擎、三供给、三保障"的七子系统：控制循环（引擎）；上下文、工具、记忆（供给）；护栏、状态、可观测（保障）；外加贯穿的错误恢复与预算。（这"引擎/供给/保障"三层，S1 的组件图沿用、C2 落地时也称"内圈/中圈/外圈"，指的是同一组。）

但本文主张：**这个七子系统的清单，是没看清一条更深的缝的切法。** 真正劈开 harness 的，是下面这把刀（它在 M5 被锻造，这里先用它重切结构）：

| | **赋能层** | **治理层** |
|---|---|---|
| 为什么存在 | 让模型**能**把事做成 | 让模型行使能动性时**可问责、有边界** |
| 补的是 | 能力的洞 | 自主性的代价 |
| 包含 | 循环、grounding、上下文组装、压缩、工具检索、推理脚手架 | 权限、记忆（作为受治存储）、审计、预算、append-only 状态、确定性旁路 |
| 判据 | 模型终将**自己又读又写** | 模型**可读、但写权威必须外置** |
| 命运 | 随模型变强而**侵蚀、消失** | **不可侵蚀** |

**关键洞察〔线 C〕**：这条缝**不在子系统之间，而是切穿每个子系统**。最好的例子是记忆——它的**机制**（抽取-存储-检索）是赋能的（补"记不住"的能力洞，会被模型吸走），它的**治理**（可删除、可审计、留在权重之外）是永久的。所以正确的思考方式不是"X 子系统是不是永久的"，而是"X 里哪部分是帮模型做成（临时）、哪部分是扣住权威（永久）"。这把整个理论从"分类法"升级成"对每个部件做关切分解"。

下面对几个子系统做关切分解，作为示范：

- **上下文子系统**：核心认知是"上下文不是一条增长的历史，是**每轮现场组装的视图**"——各层可空、按任务拼接有效上下文。典型分层：固定层（系统提示）/ 任务层（plan/todo）/ 记忆层（用户记忆）/ 知识层（RAG）/ 历史层（可压缩）。其中**组装逻辑**是赋能（终将被模型自己驱动），背后的**存储与预算**是治理（外置）。
- **工具子系统**：选择可靠性不能靠"把描述写得更好"根治（再好的描述，在大量候选中选也更易错——这是注意力的物理规律），只能靠**组织结构**根治：分组、分层、隔离，让模型永远在少数候选中选。"子 Agent"就是"组"的具象化——Agent-as-Tool 的本质是**用组织对抗规模**。工具的**调用**是赋能，工具携带的**权限元数据**是治理。
- **护栏子系统**：五道关卡守五个时刻——输入护栏（防注入：信任边界，非用户输入结构上不可作为指令）、意图护栏（控制类意图高置信度）、准备护栏（prepare 参数合法且在静态权限内）、执行护栏（权限：deny-first、按可逆性分级）、事实护栏（防幻觉：安全关键信息必须有 tool result 支撑）。五关全在治理层。详见 `harness-park-design/harness护栏安全子系统设计说明.md`。

### M4 · 编排范式：显隐连续谱

本模块统一一组看似不同的概念——Plan-and-Execute、ReAct、固定工作流、DAG、todo——揭示它们是**同一个东西在"规划显式程度"连续谱上的不同位置**。

所有编排范式核心都在做同一件事：**把复杂任务拆解成若干带依赖的子步骤**。这个"拆解的产物"是同一个，但可以不同形态存在：人预先写死的图（固定工作流）、AI 当场生成的显式对象（plan/DAG；DAG = 有向无环图，用节点与依赖边显式表达步骤顺序）、内化进状态持续重写的清单（todo）。

> 下文三个"="不是数学相等，是"同一种东西的不同形态"——读作"在……意义上等同"。

三个递进的等式：

1. **DAG = todo**（都是"拆解出的步骤集合"，区别仅在动态程度）。
2. **DAG = plan**（DAG 是 Plan-and-Execute 中"先产出的完整计划"的结构化表示），故 **DAG 编排 ≡ Plan-and-Execute**。
3. **ReAct = 隐式化的 Plan-and-Execute**（最深）：ReAct 不是 P&E 的对立面，它把规划**内化**了——plan 不再作为独立外部对象存在，而是降解为消息状态中的 todo，在每轮循环中被持续重写。规划没有消失，它溶解进了"循环 + 读写状态"。

合起来得到一个连续谱：

```
显式程度高 ←─────────────────────────────────→ 显式程度低
固定工作流        Plan-and-Execute / DAG          ReAct / todo
(人写死的图)     (AI当场生成、按图执行)         (内化为状态里持续重写的清单)
```

**驱动显式程度选择的，是可验收性**：显式 plan 是个看得见的独立对象，"它对不对、成功率多少、节点间信息传递是否完整"都可被检验；隐式 todo 灵活但难验收（每次路径不同，无法稳定度量成功率）。由此得出工程最优解：**对外显式、对内隐式**——主编排层需要可验收/可监控，用显式 plan；不需对外验收的局部（子 Agent 内部、异常重规划），用隐式 ReAct。

> **承诺时点的细辨**：等式 3 在"产出了什么"层面成立，但在"何时承诺"层面有差：真正的 Plan-and-Execute 在执行前**冻结**计划，因此能在付出执行成本*之前*验证计划；ReAct 没有冻结点，丢的不是"规划"，是"先验可验证性"。这一差异在落地时（C2）会以"高风险动作需冻结确认"的形式回来。

**内圈的显/隐**（一个具体落地约定）：一个递归 ReAct 循环驱动每轮，模型输出一个统一结构。其中——

- **隐 = 思考（thought）**：自然语言、不格式化死、驱动循环、不给用户看（但留在上下文里，且是压缩时最优先被丢/被摘要的对象）。
- **显 = plan/todo（统一为"任务"）**：结构化、给用户看、并拼回上下文驱动下一轮。

同一个结构，两个消费者：对外给人看，对内当循环状态。

### M5 · 治理理论（核心承重墙）

前面所有模块都通向这里。本模块回答：harness 里哪部分是永久的，为什么永久，以及那把重切 M3 的刀从何而来。

**第一步：每个永久子系统都是一个"治理对象"，治理永远有两面。**

- **约束面**：模型是治理的**对象**——治理作用在它身上（行动闸拦它、审计记它、预算限它）。
- **依据面**：模型是治理的**消费者**——治理是它的**输入**（读到权限就不提越权的事，读到记忆就个性化，读到预算就决定要不要继续）。

权限和记忆不是两个东西，是同一种东西（治理对象）的两面。整个永久层都是治理对象，差别只是治理的是"允许什么"（权限）、"记得什么"（记忆）、"发生过什么"（审计）、"还剩多少"（预算）。

**第二步：把两面拧成"读 / 写权威的分离"。**

- **依据面 = 模型可以"读"。** 它必须能读，否则没法好好干活——看不见权限会提越权的事，看不见记忆没法认人。
- **约束面 = 模型不能"写权威副本"。** 它可以**提议**写（"这条值得记""我想执行这个动作"），但**提交的权威留在外部**（治理来 commit）。它给不了自己权限、改不了审计、延不了预算、删不掉别人该被遗忘的记忆。

于是得到本文的**生成判据**：

> **临时层 = 模型终将自己又读又写的东西。永久层 = 模型可读、但写权威必须外置的东西。临时/永久的分界线，就是"读 / 写权威"的分界线。**

拿这把尺子扫一遍，严丝合缝，还能看出一道治理硬度的梯度：

| 治理对象 | 模型能读吗 | 模型能写吗 |
|---|---|---|
| 记忆 | 读（个性化） | 只能**提议**，外部 commit + 可删除 |
| 权限 | 读（规划） | 完全不可，给不了自己权 |
| 状态（消息即状态） | 读 | **只能 append，不能改历史** |
| 预算 | 读（决定是否继续） | 不可自己扩 |
| 审计 / trace | **可能连读都不该读** | 绝对不可写（否则能毁尸灭迹） |
| 确定性旁路 | **连进都不让进** | —— |

**第三步：永久层不是"还没被吸收"，是"逻辑上不可能被吸收"。**

治理的本质是读权与写权威的分离：被治理者能读规则，但改不了规则；改规则的是治理者。一旦把"写权威"也交还模型——美其名曰"让模型自我治理""把护栏写进提示词""让模型自己策展记忆"——你就把读者和写者合并了，而**读者 = 写者 = 没有治理**。

所以"让聪明模型自己管自己"这个梦不是还没实现，是**结构上不可能实现**：一个被治理的东西无法治理它自己。这跟模型多强毫无关系——再强，它也不能既是被约束者又是约束的权威源，否则约束是假的。

这就是治理层不朽的最终理由：**它不是"补模型的不足"，它是"把写权威留在模型之外"这件事的物理载体。模型可以无限聪明地读它、依据它、驱动自己——但那支笔，永远不能在模型手里。**

> **必须诚实面对的反驳（收窄结论）**：可被吸收的，是治理的*智能*，不是治理本身。设想模型起草自己的权限策略、生成审计规则、撰写护栏，再由一个**确定性的、模型不可再触碰的提交步骤**固化——此时"规则的作者"是模型，"写权威"仍在外部，判据不破。但这意味着永久的不是"厚重的治理逻辑"，而可能只是一个 `commit()`：治理的智能含量会像赋能层一样被内化掏空（M6"消失"的同一机制），**留在模型之外的，只是那一下不可由模型按下的提交动作**。故本文主张应收窄为：**不可被吸收的是"写-提交权威"这个薄接口，而非治理的全部体量。** 这也给下一节 M6 一个约束——"治理层加重"加的是问责的不可让渡性，未必是任何工程实体的体积（量度见 M6 的可证伪声明）。

> **〔线 A 收口预告〕** 那支笔握在谁手里？这是 C3 唯一未解的前沿。

## 层 C：怎么演化 / 怎么分野

### M6 · 动力学：翻转，不是变薄

把赋能层与治理层放到时间轴（模型能力轴）上，得到一个反直觉的命题。

大多数人以为"模型变强 → harness 变薄"。**只对一半。** 准确说是：

> **模型变强 → 临时层变薄，永久层变重。**

- 模型越强 → 赋能层越薄（它不再需要你帮它做成：grounding（把自然语言落到具体接口参数与真实对象，即"接地"）、上下文组装、推理脚手架被它自己吸收）。
- 模型越强 → 你越敢放权 → **每一分能动性的增长，都要求等量的权威被扣住** → 治理层越重。

> **"消失"的精确含义**：被吸收的是赋能层的**逻辑**——"怎么组装、怎么 grounding、怎么压缩"这部分智能内化进了模型；模型仍需外部的存储与工具接口，但那部分薄到接近透明。所以"消失"指的是**智能含量的消失，不是接口的物理消除**。

所以 harness 不会消失，它会**重心翻转**：从今天的"赋能为主"（大部分力气花在帮弱模型做成）翻向未来的"治理为主"（强模型轻松做成，但必须被问责、被限界）。今天 harness 的体积里可能 80% 是脚手架，未来 80% 是治理。

**这重写了工程投资策略〔线 C〕**：赋能层做薄、做到可随时删（它注定被下一代模型作废，投入越重越亏）；治理层做厚、做到可证明（那是唯一不会被作废的投资）。一个有用的副判据：**越靠近基础计算规律的子系统（状态持久化 = 事件溯源），不同实现越趋同；越靠近"服务谁"的子系统（记忆、护栏），越分野。**

> **可证伪声明（针对翻转命题）**：不给度量，"治理层加重"就不可证伪——治理代码占比无论升降，都能用同一套话解释，这是本命题最大的认识论风险。本文给一个操作化指标：**治理占比 = 模型不可写的控制点数 ÷ 全部控制点数**（权限闸 / 确认点 / 审计写入 / 预算闸 / 确定性旁路，比上工具调用总数）。翻转命题的**可证伪形式**是：随模型代际增强，该比值应**上升**；**若观测到它持平或下降**（即强模型让更多控制点回到模型自身可写），翻转命题即被**推翻**。关键（承 M5 的收窄）：必须数"不可写控制点"，**不能数"治理代码行数"**——后者会随治理智能被内化而下降，反而把"加重"误读成"减轻"。

（本模块由附录"翻转图"锚定。）

### M7 · 分野：服务任务 vs 服务人

M2 留下的伏笔在此展开：不同 harness 在结构上趋同，在取舍上分野，分野的根源是一条主线——**这个 agent 是服务"任务"，还是服务"人"。**

- **服务任务取向**（如编码助手）：任务相对独立、正确性要求高、单次任务往往就很复杂。最优策略是把"单次执行"做到极致可靠、可调试。倾向激进的简单、极致的上下文管理、静态的规则记忆、自动化的护栏。
- **服务人取向**（如个人陪伴助理）：同一主体长期反复交互、任务高度相关、个性化是核心价值。最优策略是"跨越多次交互持续成长"。倾向自我改进、跨会话的信息组织、动态自学的个性化记忆、人在回路的确认。

分野在各子系统的体现，以及其程度：

| 子系统 | 服务任务取向 | 服务人取向 | 分野程度 |
|---|---|---|---|
| 引擎哲学 | 激进简单、优化单次可靠 | 自我改进、优化成长曲线 | 大 |
| 记忆 | 静态规则、记"任务/项目" | 动态自学、记"用户" | **最大** |
| 护栏 | 尽量自动、少打扰 | 人在回路、该问就问 | 中 |
| 状态 | 消息即状态 | 消息即状态 | **无（基础规律层）** |

**理论要点**：分野的程度与子系统的"层次"相关——越靠近"服务谁"这个问题的子系统（记忆、引擎哲学），分野越大；越靠近基础计算规律的子系统（状态持久化），越趋同。这印证了 M6 的副判据：一个子系统是否存在标准答案，取决于它是"场景特化层"还是"基础规律层"。

（本模块由附录"二维定位图"锚定，并在 C2 用于给智慧园区定位。）

## S3 · 控制流：gather → act → verify（Claude Code 实证）

```
用户输入（可随时 Esc 打断 / 输入修正 steer，模型在下一步前读入并调整）
  → 【gather 收集】读文件/检索(agentic search)/CLAUDE.md/记忆/权限 → 现场组装上下文视图
  → 【act 行动】模型推理（隐:scratchpad/thinking）→ 选工具 → 调用
        · 动作前治理闸：可 checkpoint 的编辑→放行/auto；**外部副作用→必问 ask**
  → 工具返回 observation → 喂回循环
  → 【verify 验证】对照测试/规则/截图自查（可靠性：规则 > 视觉 > LLM-judge）
  → 未完成→repeat（course-correct）；完成→收尾
  （贯穿：context 近满→compaction；子任务→派生隔离子会话、回吐摘要；每步可中断）
```

**关键治理分叉，由 Claude Code 实证**：官方文档原话——*"Actions that affect remote systems (databases, APIs, deployments) can't be checkpointed, which is why Claude asks before running commands with external side effects."* 这正是 M3 的**读/控分叉 + ask 闸**在真实 harness 里的判据：**分界线是"能不能回滚"，不是模型强弱**。对你园区——设备控制不可回滚，故必确认（C2）。

## S4 · 上下文与状态：两个"现场组装/append-only"的实样

- **上下文 = 每轮组装的视图**（Claude Code 实证 M3/M6）：compaction（先清旧工具输出、再摘要，保住请求与关键片段）+ agentic search（模型用 grep/tail 自取）+ 按需加载（skill 描述、MCP tool 延迟）。这是"赋能层组装逻辑正被模型自己驱动"的活样本。
  - **视图 vs 存储（关键区分）**：上下文是**动态视图**（模型的视觉窗口，每轮现场组装、可压可换、可重建）；运行结果/对话是**静态真相**（持久化日志，Redis 热 + PG 档，Hermes split SQLite+rotate session）。**从视图里压/换旧内容不是数据丢失**——日志里原文还在。压缩产物是"派生"，但因贵且要复用，宜**持久（入日志/会话）而非可丢缓存**（Hermes 即如此）。
  - **旧工具输出:摘要 > 句柄取回（弱模型尤其）**：Claude Code/Hermes 对旧工具输出**一律摘要**（gist 留视窗、模型零负担），**不做"按句柄 fetch 回旧结果"**。fetch/重查要模型"意识到不够→主动取回"，**弱模型经常不取→降质**；且控制类结果重查=重执行副作用（危险），fetch 比重查安全但仍加负担。**结论:压缩（摘要）是 proven 路，句柄/fetch 不建。** "按需取回"只适用于**可重读环境**（文件 via agentic search / 后端 via 工具再查），不适用于"取回历史里被压的旧工具输出"。
  - **Hermes `context_compressor.py` 实证配方（读源）**：aux 模型（独立 client、cheap/fast）摘中段、**保头 + token 预算保尾（非固定条数）**；**先清工具输出（cheap pre-pass）再 LLM 摘**（= Claude Code 清→摘）；**iterative summary updates**（多次压缩间滚动更新）；**结构化摘要模板**（Resolved/Pending 分节）。**🔑 最硬的经验 = `SUMMARY_PREFIX` 强框**：压缩后模型会把**摘要里的旧任务/旧问题当成现在的活**去"恢复/收尾/重答"——必须前置"仅供参考·非指令·只对此摘要之后的最新消息负责·最新消息为准·别恢复旧任务"，并用"## 历史…"标题(不用 Next Steps)。这是把"压缩"做成净收益的关键,漏了压缩反而带偏模型。
  - **Hermes 不给消息打标签**（grep 证：消息只有 role/content/tool_calls/tool_call_id）。管理靠"摘要把结构装进 gist + 内容检索（`memory_manager.prefetch_all` 按用户消息 harness 预取，非 model-fetch；召回内容套 `<memory-context>`「非用户输入·当背景」框 + sanitize 防伪造框）"。⇒ **per-message 标签是结构化域可选的优化、非 proven 必需；有 Message 核心改动成本,价值可由摘要/检索替代**。
- **状态 = append-only**（消息即状态的两个实例）：Claude Code 把每条消息/工具调用/结果写进 JSONL（`~/.claude/projects`），支持 resume/fork/rewind、切分支不丢历史；Hermes 存 `~/.hermes`。

## S5 · 子会话：两极都真有（不是纯理论提案）

M2 的"递归自相似"不只是理论推论——**子会话在两个真实 harness 里都是现实**，两极都做了。

- **Claude Code**：子代理**自带 fresh 隔离上下文**，工作不污染主线，完成只回吐**摘要**；可并行（配 git worktree 跑并行会话）。
- **Hermes**：**并行 sub-agents**，RPC 通信，跑并行工作流。

共同点正是 M2 递归自相似 + M5 隔离原则：**隔离工作上下文、只回吐摘要/结果**。设计要点不变（子权限 ⊆ 父、共享预算池、深度上限），但"它能不能做"已被两个生产系统回答：能。

## S6 · 贯穿：可观测/检查点 + 预算/上限

- **可观测/检查点**：Claude Code 的 checkpoint（编辑前快照）+ `/context`（看占用）+ verbose 日志；对模型**只读不可改**是审计底线。
- **预算/上限**：Claude Code 的 context limit + compaction 阈值 + **thrashing-error**——单个超大输出导致"摘要后立刻又满"时，几次后**停下报错而非死循环**。这是"预算耗尽要如实停、不伪装继续"的真实样本。

## S7 · 治理工具对照：两极如何各自"把笔留在模型外"

替代抽象契约，直接看两个真实系统用什么工具持笔（C1 的发现做实到模块级）：

| 治理对象 | Claude Code 的工具（服务任务） | Hermes 的工具（服务人） |
|---|---|---|
| 行动权威 | 权限模式 + settings 允许清单 + org 策略；**外部副作用必问** | 自托管下用户即唯一权威 |
| 可逆/回滚 | 编辑前快照 + Esc 回退；不可回滚的副作用→必问 | 本地操作 |
| 真相源写保护 | **不可改测试、防篡改 JSON 清单、git 版本控制** | — |
| 记忆治理 | auto memory = 项目学习（**工程流程**持笔） | **数据主权**：本地、零遥测、用户可删（**用户**持笔） |
| 审计 | JSONL 会话日志、verbose | 本地日志 |

**共同铁律**：写治理对象的从来不是模型。差别只在持笔者——**服务任务交给工程流程/版本控制，服务人交回用户（自托管）**。M5"谁持笔"在两个真实系统上做实。

## S8 · 分野总表 + 落地指针

| 模块 | 服务任务（Claude Code） | 服务人（Hermes） | 分野 |
|---|---|---|---|
| 记忆 | 项目/静态（MEMORY.md, git） | 用户/自学（Honcho, FTS） | 最大 |
| 引擎哲学 | 单次可靠、不自改 | 自我改进（skills 自创） | 大 |
| 触达/运行 | 终端/会话式 | 多平台网关 + cron 后台常驻 | 大 |
| 护栏 | checkpoint + ask（可逆兜底） | 数据主权 | 中 |
| 子会话 | 隔离回摘要 | 并行 RPC | 小（都有） |
| 状态 | JSONL append-only | 本地 append | 无（基础规律层） |

**落到本项目（详见 C2，不在本 Part 预设旧代码）**：园区助手是"服务任务 × 不可逆"，故取 **Claude Code 这一极的模块组合**——显式编排、checkpoint/ask、项目级记忆；Hermes 的自学记忆、多平台网关、自我改进**后置**。现有 `capability_platform` 各目录如何对接这些模块，是 C2 的落地工作。

## S9 · 工程硬骨头（两个真实 harness 教的六课）

1. **验证要有抓手**（Claude Code）：给测试/截图/规则让 agent 自查；可靠性规则 > 视觉 > LLM-judge。无抓手的验证形同虚设。
2. **压缩会 thrashing**（Claude Code）：单个超大输出会让"摘要后立刻又满"——必须设"几次后停并报错"，把"预算耗尽如实停"做成机制，不死循环。
3. **不可回滚 = 必问边界**（Claude Code）：可 checkpoint 的放行、不可 checkpoint 的必问。读/控分叉的工程判据是**能不能回滚**——你园区的设备控制不可回滚，故必确认。
4. **记忆抽取要自动且可治理**（Hermes）：模型自判价值→抽取→检索是可行的（Hermes 实证）；但关于人的记忆必须本地、可删（数据主权），否则治理失守。
5. **自我改进有边界**（Hermes 自学 vs Claude Code 不自改）：服务任务域**慎用**自改（单次可靠优先），服务人域才值得自学——别把 Hermes 的 skills 自创搬进一个要可验收的事务系统。
6. **人在回路是一等公民**（Claude Code）：随时可 Esc 打断 / 输入 steer——这不是异常路径，是主循环的一部分。高风险事务系统尤其要把"该问就问/可随时介入"做成常态，而非例外。

# 总二 · 收敛与应用

### C1 · 实证：理论与真实实现的对照

把上述纯演绎的理论，扔进三个真实实现——Claude Code / Claude Agent SDK（服务任务极）、Hermes Agent（服务人极）、Anthropic 的 harness 工程实践——逐条检验。结论：**理论站住了，核心判据被逐条坐实，唯一需补的是一件治理工具。**

> **C1 与 分二 的分工**：两者用同一批证据（Claude Code / Hermes），但**本节验证 M1–M7 的理论命题**（缝是否存在、组织是否胜过描述、记忆是否分野），**分二 则从同一对 harness 提取可搭的模块结构**。一个验命题、一个定模块，互补不重复——模块级细节见 分二/S1–S9。

**坐实的部分：**

- **〔线 A〕读/写权威之缝在野外被找到。** Anthropic 长跑 harness 中，工程师 *"prevents agents from modifying critical files… It is unacceptable to remove or edit tests"*——**测试（真相源）被从外部写保护**；真相清单选 JSON 而非 Markdown，理由是 *"the model is less likely to inappropriately change or overwrite JSON files"*——**专挑模型更难篡改的格式装治理对象**。这正是"模型可读、不可写权威"。我们从判据演绎，他们从踩坑长出，殊途同归。
- **组装内化。** Claude Agent SDK 的 **"agentic search"**：模型用 `grep`/`tail` 自己选择性加载上下文，外加 compaction 自动压缩。M3/M6 预言的"赋能层（组装/压缩）塌进模型"，正在发生。
- **子会话隔离。** SDK：*"subagents use their own isolated context windows, and only send relevant information back to the orchestrator"*——精确命中"隔离工作上下文、只回吐归一化结果"。
- **输出侧/事实护栏最不可靠。** SDK 把验证排序：规则校验 > 视觉 > LLM-as-judge（明确标注 *"less robust"*），呼应"幻觉最难测"。
- **〔线 B〕分野表逐格命中。** Claude Code（服务任务）记的是"项目"（git / progress.txt / feature_list.json，每会话重建）；Hermes Agent（服务人）记的是"用户"（Honcho 用户建模 + 模型自判抽取 + 检索召回），并**原样实现了本文 M3 描述的长期记忆设计**（模型判断对话有无价值 → 抽取 → 存储 → 检索）。引擎哲学：Claude Code 优化单次可靠，Hermes 自我改进（复杂任务后自动写成可复用 skill）。状态：两者都"消息即状态 + 检索"，**趋同**——恰在基础规律层。

**需补正的部分：围栏可替代确认。** Anthropic 的长跑 harness 几乎**没有 human-in-the-loop**，靠**环境围栏**（*"You'll only be able to edit files in this directory"*）+ **可逆性**（git revert）就敢让 agent 全自动跑。这给治理层补了一条：**治理至少有两件工具——"事前确认"与"环境围栏"，选哪件取决于"可逆性 × 爆炸半径"。** 可沙箱、可回滚 → 用围栏跳过确认；不可沙箱、不可逆 → 确认不可省。

**两件治理工具，两个持笔者。** Claude Code 治理的是"任务的真相源"，工具是写保护 + 版本控制，**笔握在工程流程手里**；Hermes 治理的是"一个人的记忆"，工具是**数据主权**（自托管、本地、可删除），**笔握在用户本人手里**。两者都遵守同一铁律——**写治理对象的，永远不是模型本身**——只是把笔交给了与"治理谁"相称的不同外部主体。

### C2 · 落地：智慧园区助手

把理论落到一个真实项目：一个把已建成的园区前后端业务（设备查询/控制、工单等）改成自然语言入口的助手。

**定位〔线 B + 线 C〕**：在二维图上，它是**服务任务 × 不可逆**（左下角）——对标 Claude Code 而非 Hermes。但它的域**不可沙箱**（真实设备控制），所以治理工具**必须是确认，不能是围栏**。读/查可逆 → 可全自动；控/写不可逆且出真实世界 → 确认不可省。这不是过度设计，是域逼的。

**架构定位**：harness ≠ 替代后端。它是 AI 服务的**管理/边界/编排层**，获取后端能力来赋能，**不持有业务权威**（权限/事务/审计归后端）。对齐工业北极星（腾讯总部园区 V6 五层架构）：

```
C 端入口  →  AI 对话引擎/数字人（中枢：意图识别·编排·降级）  →  子 Agent 能力层（经 MCP）  →  数字底座（后端权威）
```

中间两层就是项目的主战场。

**三环设计**（= 分二/S2 那组参考模块在本项目的具体排布：内圈≈引擎，中圈≈供给，外圈≈保障，贯穿≈治理旁路）：

- **内圈**：一个递归 ReAct 循环（主子会话共用）。显=plan/todo，隐=思考；消息即状态。主子**共享**身份/权限/长期记忆/预算池/持久化根，**隔离**工作上下文，子只回吐归一化结果。子会话权限 ⊆ 父会话权限（不可通过递归提权）。
- **中圈（供给）**：上下文（五层分层组装、按任务、历史层与旧思考优先压缩）/ 记忆（工作·短期·长期，长期=模型自判抽取+检索）/ 工具（注册表 + 权限元数据）。
- **外圈（保障）**：护栏（五道护栏关卡：输入 / 意图 / 准备 / 执行 / 事实；执行前与执行时 = 默认 deny → 权限校验 → 可逆性判定）/ 会话与状态（消息即状态、append-only）。
- **贯穿**：可观测/评测 + 预算（主子共享池 = 递归总燃料闸 + 深度上限 + 单子抽取上限；耗尽则降级收尾或如实停报，绝不伪装完成）。

**建设顺序**（按"观察到的痛"分期，禁止全部子系统一次全上）：

1. **基线**：选 `device.status.query` 一个读能力，写 15–20 条评测用例，跑出基线命中率；打开 trace。
2. **控制闭环**：`device.control_ticket.prepare` 接 confirm 闸，跑通 prepare → 展示 → 确认 → 执行；后端写接口加幂等键。
3. **验证可扩展**：照设备 manifest 模板复制出工单域，证明"加一个域 = 填模板"。
4. **对齐 MCP**：把 backend-facing 工具封成 MCP server，带统一注册/权限/日志元数据。
5. **按痛加**：记忆、跨轮引用、降级调度——测到痛再上。

**成功判据**（是事务系统，不是问答助手）：任务完成率、消歧准确率、**错误动作率/越权动作率（趋零，安全红线）**、澄清反问精准度。可直接照搬北极星需求书的非功能表（可用性≥99.9%、注入防御、敏感信息保护、知识更新延迟）当基线。

**事实锚点**（已存在，复用即可）：能力 manifest 见 `src/smart_park_assistant/assistant_core/capability_platform/capabilities/manifests/*.json`（已含 `risk` / `fallback_policy` / `eval_cases`）；风险等级见 `src/smart_park_assistant/assistant_core/harness/policy.py`（read/draft/ticket/execute，其中 execute 被 deny、控制转 ticket）。

**两处落地暗礁（必须设计进去，否则治理形同虚设）**：

- **确认疲劳**：事务系统若每个控制动作都弹确认，操作员会无脑点"是"，确认退化成橡皮图章——**看起来合规、实则没把关**。须按风险分级（只对不可逆/高影响动作确认）、批量聚合、并对"连续秒确认"做行为监测。**问太多 = 没问**，这是安全红线系统的经典反噬。
- **MCP 自身是新的信任边界**：把后端工具封成 MCP server 不是纯收益——它引入新攻击面（业界已有 Claude Code 项目文件 RCE 一类的真实披露），**MCP 本身成了一个治理对象**。这与全文"信任边界"主题一致：对 MCP 的注册/权限/来源同样要 deny-first，别把它当可信内部。

### C3 · 前沿：谁持笔

线 A 在此收口，但收的是一个**敞口**。

M5 证明了永久层不可被模型吸收——写治理对象那支笔必须在模型之外。但**那支笔握在谁手里？** 这是全文唯一没有工程解的问题，也是 agent 系统迟早撞上的边界：

- 若笔在**人**手里 → harness 的治理层最终是"把人类权威接进自动化"的接口，其可信上限 = 那个人的可信度与带宽。能动性一放大，人就成了瓶颈（"高风险动作人在回路"正是这个瓶颈的显形）。
- 若笔下放给**另一个自动化治理者** → 那个治理者本身又是"被治理的东西"，于是递归：**谁来治理治理者？** 这条递归不像子 Agent 那样优雅触底。
- **但"不收敛"不是定论**：分布式系统已有一个真实的触底构造——**拜占庭容错 / 法定人数（BFT/quorum）**：一群被治理者通过协议**集体自治**，无单一外部持笔者却可信。它证明"被治理者治理自己"在工程上可达成。代价是它依赖"多数诚实"假设；移到园区这种**有真实世界后果、参与方权责不对称**的场景能否成立仍是开问题——但它把 C3 从"死局"降级为"有已知部分解的难题"。
- 另一条触底方式：治理本身变成一套**可审计、可问责、不依赖单点善意**的规则系统（如法律之于权力）——即"治理者也只是另一支被外部记录约束的笔"。

C1 给了这个敞口一个**域依赖的部分答案**：**服务人 → 笔交回用户**（Hermes 自托管、可删的个人记忆）；**服务任务 → 笔交给可问责的流程**（Claude Code 的 git、不可改的测试）。但"谁治理那个治理者"在工业界也仍是敞口——真实实现是用"围栏 + 可逆"**绕过**它，不是**回答**它；一旦动作不可逆（如园区设备），绕道失效，这道坎照样横在那里。

**结论**：harness 的技术部分，到那条缝为止，基本已经想清楚。剩下的两个真问题都不在代码里——一个是制度问题（持笔者的可信度如何被证明），一个是纪律问题（每次有人喊"让模型自己管自己更高效"，都是在把写权威往模型手里塞一点；识别并守住那条缝，是 harness 工程唯一不能妥协的纪律）。**harness 工程的尽头，是治理工程的开头。**

# 局限与边界（同行评审后补）

为免"自洽"被误读为"完备"，明确标出五处边界：

1. **翻转命题的可证伪性**：本是最大认识论风险，已在 M6 补一个可操作、可被推翻的度量（不可写控制点占比）。请据该度量、而非标题语气判断翻转命题；它仍是**假说，不是定理**。
2. **中心论点是"定义封闭"的**：M5 那条判据靠把"治理"定义为"读/写权威分离"来保证为真，故偏分析性。已在 M5 收窄为"不可被吸收的是写-提交权威这个薄接口，而非治理的全部体量"——治理的*智能*会像赋能层一样被内化。
3. **成本/延迟被简化**：本文把"有限且昂贵"凝结为治理层的"预算对象"。但成本-延迟-质量三角其实是贯穿赋能层的连续优化变量（compaction 频率、子会话数、verify 深度都是成本函数）；为维护"两层"二分的简洁，未展开。
4. **安全对抗的动态性、模型协同演化未纳入**：护栏被当作静态三关，但注入/越狱是会适应的军备竞赛；模型被当可换的外生黑箱，而现实是 harness 与后训练互相塑造（工具使用、agentic 行为被训进模型）——"翻转"中赋能层的"被吸收"，部分其实是"被有意训练进模型"。这两条都会改变"谁主动、多快"的图景。
5. **实证样本 n=2 且非独立**：M2 的"趋同演化"与全文实证只立足 Claude Code + Hermes，且两者都深受 Anthropic/ReAct 范式影响。相关结论应读作"两个领先实现的一致选择"，**而非"普适规律"**。

**一句话**：本文最硬的是那把刀——**读/写权威之缝**，一条可重切 harness 结构的生成判据；最该谨慎对待的是包在它外面的演化哲学（翻转必然论），已为其补了可证伪度量与收窄结论，但它仍是雄辩而非定论。

## 附录 C · 术语表

本文核心术语：

- **赋能层 / 治理层**：harness 的两类部件；判据是"模型能否拥有写权威"。
- **读/写权威之缝**：临时与永久的分界线；模型可读、但写权威必须外置。
- **消息即状态**：把全部处境表达成一个 append-only（只追加、不改历史）消息序列，一套结构同时给持久化/恢复/回放/审计。它是"事件溯源"（event sourcing，下条）在 agent 上的实例。
- **关切分解**：不问"某子系统是不是永久的"，而是把它拆成"赋能关切（会被吸收）"和"治理关切（不可侵蚀）"两面分别判断。
- **显/隐**：显=plan/todo（给用户看 + 拼回上下文）；隐=思考（不给用户看，驱动循环）。
- **服务任务 / 服务人**：分野主线；前者优化单次可靠、记任务，后者优化成长、记用户。
- **确定性旁路**：不可犯错的链路不进引擎，走确定性规则。

通用技术术语（供不熟悉的读者）：

- **grounding（接地/落地）**：把模糊的自然语言落到具体的接口参数、枚举值、真实对象（如"3 号楼空调"→ 某 device_id）。
- **RAG（检索增强生成）**：先从外部知识库检索相关片段，再喂给模型作答，以约束其不凭空生成。
- **DAG（有向无环图）**：用节点 + 依赖边显式表达"哪些步骤、谁依赖谁"的结构。
- **事件溯源（event sourcing）**：不存"当前状态"，只存一条只追加的事件日志，任意时刻状态由重放日志重建；与数据库预写日志同源。
- **MCP（Model Context Protocol）**：把后端系统的能力包装成标准化"工具"供模型调用的协议，统一注册/权限/鉴权。
- **围栏 / 确认 / 降级**：三种治理动作。围栏=用环境（沙箱、目录、权限）限定模型能触及的范围；确认=高风险动作执行前要人点头；降级=能力不足或预算耗尽时退到更保守的安全行为（拒答、收尾、如实停报），绝不伪装完成。
