# 语音交互子系统 · 设计(v1 · 收敛定稿 · 真机已验)

> **方法**:语音不是重造编排——既有实时协议(主 WS + run/工具/票据/事件)已是完整编排层,**语音 = 媒体侧薄胶水**(音频 ↔ ASR/TTS + VAD/打断),对大脑透明(所有输入归一成 run)。grounding **对准我们生产实际跑的引擎 = FunASR runtime 开源版(6011/6012)**:① **轮次/打断/EoU**——⚠️ FunASR runtime 客户端协议**只收** `mode/chunk_size/chunk_interval/encoder·decoder_chunk_look_back/is_speaking/hotwords/itn`,**无 silence/semantic 开关**(静默端点在服务端 fsmn-vad 模型、客户端调不动)。所以契约 `turn_detection` = **适配层意图位、用中性名**(`endpoint_silence_ms/semantic_endpoint`),**不抄阿里云 SaaS 的 `max_sentence_silence`**(那是 Model Studio SaaS、我们没跑)、**不抄 OpenAI**;唯一对得上 runtime 的真字段 = `is_speaking`(PTT)。barge-in = WS 下客户端管播放→本地停播(纯应用层,与 FunASR 无关)。**不上 OAC 的 LLM 判官打断**(avatar 加法,延迟 + GPU1 满双否)。升级位(语义)的代码参考 = OpenAvatarChat/FireRedChat,**只当升级期片段参考,不当现在标尺**;**且语义升级要换/加底座(阿里云 SaaS `semantic_punctuation_enabled` 或自挂 CPU turn-detector),非翻 bool 即生效**;② **传输(单 WS multiplex)= 阿里云 ISI(text指令+binary音频)逐字同款**;③ **ASR 抗噪 = Paraformer-v2**。**设计纪律:最小实现 + schema 留中性扩展位默认 off。** 理论 = 数字人深度学习文档 §1-9;真接口 = 90 上 FunASR 6011/6012 + CosyVoice2 6014;端到端真机已验(2026-06)。
> **核心判据(一把刀)**:**媒体面只做"翻译"(音频 ↔ 协议事件),不做"编排"(run/工具/上下文/权威全委托)。** 每个组件问一句:这是翻译还是编排?是编排 → 不属于本子系统。这把刀劈开"本子系统 vs 委托大脑/后端/前端",也是"薄到可删"的判据。
> **v1 主轴**:① **单 WS 多路复用**(text 控制 + binary 音频,阿里 ISI 逐字同款);② **交互场景分档**(室内安静=连续+本地VAD / 室外嘈杂=PTT,PTT 是正解非降级);③ **打断 = 客户端本地先停 + 后端硬 `task.cancel`**(已验真停进行中工具/RAG/LLM);④ **声学治本在交互层(PTT)+ 模型层(Paraformer-v2)**,信号处理(前端/服务端降噪)是需 A/B 的末位;⑤ **媒体面薄、不持权威**——run 编排/上下文/权限全委托大脑与后端。
> **状态**:骨架**已建已验**(media+realtime 108 测绿,90 端到端出声);待建集中在**前端接下行**与**声学室外档**。唯一不可控外部依赖 = 内置 AEC 能否消 Web Audio 播放(逐端实测,决定真全双工)。

## 一、定位与职责边界

**一句话**:后端 = ASR/TTS/设备执行底座;大脑(agent_runtime) = run 编排;**本子系统 = 把"音频"翻译成协议事件、再翻译回"音频"的媒体侧胶水**;前端 = 采集/播放/本地 VAD 的笔。

| 关切 | 归属 |
|---|---|
| 归一化16k / 句聚合 / 文本清洗 / 排期下行帧 / 媒体会话生命周期 / 声学策略 / 打断媒体侧(media.clear→停下行) | **本子系统**(`assistant_core/media` + `api/realtime.py` 媒体部分) |
| FunASR 原生 → `asr.*` 字段映射 + transcript_id 签发;CosyVoice 原生 → `tts.*` + 音频帧映射 | **本子系统**(薄胶水) |
| run 编排 / 工具·RAG·LLM / **run 取消(硬 task.cancel)** / 上下文 | 委托大脑 `agent_runtime`(透明) |
| ASR/TTS 模型推理(6011/6012/6014)/ 设备控制执行 | 委托后端 |
| 采集(getUserMedia/recorderManager)/ 本地 VAD / AEC / 排期播放 / PTT↔连续档切换 | 委托前端(金标准 = `web/spa-voice/spa-voice.js`) |
| 业务权限 / 事务 / 审计 / 协议控制面信令(connection/run/ticket) | **不归我们**(后端 + realtime gateway 控制侧) |

**边界铁律**:媒体面**不碰 run 编排、不碰大脑**;它只对接 `media_session / asr.* / tts.* / media.clear` 抽象,大脑是谁、是否带工具,媒体面无感——因为"所有输入最后都归一成 run"。
> ⚠️ **诚实标注两条"不那么干净"的现实**:① **透明是非对称的**——前向(音频→run.create)对大脑透明,但**打断(barge-in)必然反向伸进 run 生命周期**(media.clear→run_store.cancel→硬 task.cancel),这是 barge-in 固有的耦合,不是脏设计但要承认。② **子系统边界是概念的,不是物理的**——媒体管线 `media/` 是干净独立模块,但网关那半截**和控制面信令(connection/run/ticket)挤在同一个 `realtime.py`(2092 行)里**,不像 `agent_tools/` 有独立物理边界;"本子系统"= 干净的 `media/` + 共享大文件的媒体切片,这影响可测试/可维护(见 §十 风险)。

## 二、统一原则(v1 核心)

1. **媒体面对大脑透明**:文本/语音/图片三类输入都归一成 `run.create`;换大脑(agent_runtime↔任何)契约不变。语音只是"多一条把音频翻成 run 输入、把 message.delta 翻回音频"的链。
2. **单 WS 多路复用**:`text` 帧 = 指令/事件,`binary` 帧 = 音频,同一条 `/app/realtime/ws`。**打断快靠小帧 + 客户端管播放,不靠连接数**——阿里/OpenAI 都单 WS,双 WS/WebRTC 进附录。
3. **治本在交互层与模型层,信号处理是末位**:嘈杂场景的解药优先级 = PTT(确定性边界)> 抗噪 ASR 模型(Paraformer-v2)> 浏览器 NS 档位 > 服务端深度降噪(需 A/B,有"SE 伪影反降准"实证风险)。**先动交互与模型,再谈降噪算法。**
4. **媒体不可重放、不持权威**:音频二进制帧**不进 AppEvent 事件日志**(信令/数据解耦),且不可重放;韧性靠客户端兜底(断连即停录+提示重说)。
5. **可逆性沿用主子系统纪律**:语音里的控制(关空调等)仍走 `operation_ticket`(真下发+读回+可视确认卡),媒体面不开"语音直执行"的缝。

## 三、组件化结构(三条链)

契约 = 音频进 → 协议事件出 / message 进 → 音频出。三条链都收口在唯一 WS 端点 `api/realtime.py::realtime_ws`(`@router.websocket("/app/realtime/ws")`,全仓唯一)。

```
【上行链 · 音频→asr.final】                          入口:realtime.py:259 receive 循环(message["bytes"]→_handle_media_frame)
  binary 帧 → decode_media_audio_frame(protocol.py:68)
   → 归一化16k(audio_codec.resample_pcm16,scipy resample_poly 抗混叠,§7.4 关卡二)
   → nearfield RMS 门控(audio_codec.rms_energy,低能量远场静音化不丢帧)
   → FunASR 2pass(asr.py:DualAsrSession,6011 partial / 6012 final,一条上游连接跨多句 asr.py:66)
   → 剥情绪标签(_strip_asr_tags)→ asr.partial / asr.final(+transcript_id)
   → promotion:asr.final 幂等创建 run(_start_run_from_transcript)

【下行链 · message→音频】                            入口:realtime.py:206 make_downlink(有 active media_session 即挂)
  订 message.delta(大脑文本流)
   → 句聚合(sentence_aggregator,首片段切逗号降首包,§4.2)
   → 文本清洗(text_cleaning,去 markdown/emoji,§18.3)
   → CosyVoice stream(tts.py:CosyVoiceClient,注册音色 spa_voice,首包 ~0.04s)
   → Pcm24kFramer(audio_codec.py:96,裸 PCM24k 切 960B/20ms 帧)
   → send_bytes 主 WS(track=tts_audio)+ tts.started/completed/cancelled 事件

【打断链 · barge-in→run.cancel】                     入口:realtime.py:391 MEDIA_CLEAR → _handle_media_clear → _barge_in_active_runs(707)
  客户端本地 VAD 探开口 → 本地先停播+清缓冲 → media.clear
   → run.cancelling(reason=barge_in)→ run_store.cancel(state.py:155)→ 硬 session.task.cancel(161)
   → CancelledError 在当前 await 点抛 → 真停 httpx 工具/Milvus/LLM
   → tts.cancelled / message.cancelled / run.cancelled(downlink.cancel 停下行)
```

每段是接缝:换 ASR 模型只动上行链映射;换 TTS 只动下行链;打断协议不变。
> **串联入口** = `agent_runtime/api/ws_app.py`(8020 实启)借 `assistant_core/api/realtime.py` 的 router,注入 agent_runtime 的 `AgentGraphRunner` 作大脑(`app.state.assistant_chat_service_factory`)。媒体管线全在 `assistant_core/media/`,被 realtime gateway 调用。

## 四、上行(音频 → asr.final)——【定稿】

**胶水只干四件**:① 归一化16k ② FunASR 输出→`asr.*` 字段映射 ③ 签发 transcript_id ④ nearfield 门控;识别/切句全靠 FunASR runtime。

| FunASR 2pass 原生 | 协议事件 | 落点 |
|---|---|---|
| 6011 流式 partial | `asr.partial`{text} | `asr.py` 流式会话 |
| 6012 整句(fsmn-vad speech_end 锁定) | `asr.final`{transcript_id,text,start/end_ms} | 管线签发 transcript_id |
| speech_end | 触发 final + run promotion | 切句引爆点 |

**铁律**:
1. **上行帧 schema 注册期钉死**:`MediaAudioFrameHeader`(protocol.py:25)`type=media.audio.frame` / `track=audio_in`(Literal 限定);`media_session.create` 的 `AudioInputConfig`(realtime/protocol.py)`sample_rate=16000 / mode=2pass / chunk_size / itn` 逐字段。**前端字段已实测吻合**(移动端 audioFrame 逐字段对得上);⚠️ **但只证明字段对,全握手(hello/鉴权/auto_run_on_final→run)整链未实测**——落地第一步要跑通看哪断。
2. **上游连接跨句复用**(asr.py:66:"一条上游连接承载多句,只在 media_session.close/disconnect 才 aclose")——对齐阿里"连接复用,任务结束无需重连"。
3. **归一化是关卡二**(§7.4):前端理论上发 16k,后端 media WS 入口仍校验/兜底重采样(`resample_pcm16` 抗混叠)。

**砍掉的**:cam++ 说话人过滤(pVAD)—— nearfield 门控先顶,公共多人才需,本场景近讲不做。

## 五、声学(分层方案)——【定稿 · 室外稳健默认】

**不是一个 NS 开关能拍死的**(产品画像 = 室内安静 + 室外开放嘈杂混用)。按"治本→末位"四层叠:

| 层 | 室内安静档 | 室外嘈杂档 | 依据 |
|---|---|---|---|
| **1 交互层(治本)** | 连续采集 + 本地 VAD | **PTT 按住说话** | PTT 给确定性边界,消灭"噪声触发 VAD/灌进 ASR";行业正解非降级 |
| **2 浏览器 NS** | 关/弱(护辅音,已验) | **开**(灌噪比削辅音危害大) | 切档用**重新 getUserMedia 重取流**,**非 applyConstraints**(MDN Limited availability,热切可能静默无效) |
| **3 ASR 模型** | Paraformer 流式 | **优先评估 Paraformer-v2**(官方抗噪型)或加噪重训(MUSAN/RIR) | **抗噪第一责任在模型,不在前端降噪堆叠**;⚠️ 评估前先核两个前置:**v2 在 90 FunASR 上是否 drop-in、是否支持流式 partial**(现 6011 是流式),再谈 WER |
| **4 服务端 SE 降噪** | 不开 | 可选、**必须 A/B 实测 WER** | 独立 SE 前端伪影 > 残噪有"反降准"实证(arXiv 2311.11599),不默认开 |

**nearfield RMS 门控的边界要标清**:能量阈值门控,只挡"安静环境远处低能量人声",**挡不住室外高能量噪声**——别让它显得能解决室外。

**稳健默认**:室外 = PTT + 浏览器 NS 开 + Paraformer-v2;室内 = 连续 + 本地 VAD + 弱/关 NS。**两档用户手动选**(巡检员自知场景,比自适应自动跳档可靠);上线前真实室外 A/B 定默认。

## 六、下行(message → 音频)——【定稿】

**胶水只干三件**:① 句聚合 ② 文本清洗(自写,P0,连 OAC 都缺)③ chunk→媒体帧 + tts 映射。

| CosyVoice 原生 | 协议 | 落点 |
|---|---|---|
| `inference_zero_shot_spk(stream)` chunk | 主 WS binary(track=tts_audio) | tts.py:`_stream_spk`,注册音色免每次上传 |
| 合成始/终/中止 | `tts.started`/`completed`/`cancelled` | downlink.py:DownlinkAudioRunner |

> ⚠️ **守契约**:`tts.segment` 是协议**预留、本实现未发**(见 `app-realtime-protocol.md` §6.10、runtime-logic §10 注)——下行只发 `tts.started/completed/cancelled` + 音频帧,**不发 tts.segment**。

**铁律**:
1. **下行 = 裸 PCM24k**(Pcm24kFramer,960B/20ms,§1.2 零编码延迟、无 libopus 依赖);Opus 是可选带宽层(`OpusEncoder24k` 存在但未接)。
2. **`make_downlink` 异常全包,TTS 失败不破 answer**(realtime.py:211:任何失败留 run 文本态运行,语音输出绝不打断回答)。
3. **三棒接力 + 排期播放**(§4.2/§4.5):句聚合→流式合成→边出边发;前端 `nextPlayTime` 游标 + `playingSources` 排期(金标准 spa-voice.js)。
4. **后端早在发,前端却丢弃**(现状缺口):前端(移动 aiPages / PC wsChat)**丢 tts_audio、改放本地 speechSynthesis**——`make_downlink` 只要有 media_session 就发 pcm_stream,所以**接住下行是纯前端活、后端零改**。

**待建**:TTS 到 6014 连接池化(模块级共享 AsyncClient),**前提先确认 6014 router 支持 HTTP keepalive**,否则池化无效。

## 七、打断(barge-in)——【定稿 · 真停已验】

**三铁律(§5)落地**:

| 铁律 | 落地 | 状态 |
|---|---|---|
| 1 前端先行、本地停播 | 客户端本地 VAD → 立即本地停播+清缓冲 → media.clear | ✅ SDK `_playbackActive` |
| 2 信令不被音频堵 | 小帧 + 客户端本地先停(感知停顿不等信令往返)| ✅ 单 WS 足够 |
| 3 LLM/工具可取消 | run_store.cancel → **硬 `session.task.cancel()`**(state.py:161) | ✅ **已验** |

**★关键核查结论(2026-06,read-through 闭环)**:`run_store.cancel` 不是协作信号,而是**硬 task.cancel**;agent_runtime 全链异步(`graph.astream` → `supervise` async → `await tool.run` → 网关 `httpx.AsyncClient` / Milvus `await`),无 requests/time.sleep/run_in_executor 同步盲点 → **CancelledError 在当前 await 点抛出,真停进行中的工具/RAG/LLM**;BaseException 不被 `except Exception` 误吞。**"工具不可取消"非缺口**(06-18"埋检查点"过时,硬取消更强)。`_BARGE_IN_TEARDOWN_TIMEOUT=5s` 是给 `downlink.aclose`(CosyVoice 合成中途卡)兜底,**不是等工具**。

**两档双工(钥匙 = AEC)**:
- 保底 `echo_guard=true`:出声丢 ASR 防自打断,打断靠铁律1。⚠️ **保底也需客户端 echo 处理**——本地 VAD 在外放时也在听,无 AEC 会把 TTS 当用户开口假打断;需内置 AEC 或高阈值/own-speech 门控,**非"完全不依赖 AEC"**。
- 升级 `echo_guard=false`(真全双工):前提 = 内置 AEC 实测能消 Web Audio 播放(⚠️ 浏览器 AEC 对 Web Audio 常失效,逐端测;手机App/PC 大概率行,小程序不定)。

**打断:实现最小档(任务级)+ 预留升级位(照阿里:留开关不剥)。** 独立行业评估纠正:本项目=有屏任务型工具,**别上 OAC 的 LLM 判官打断**(3s 超时不在 <150-300ms 预算 + GPU1 已满 + 逆 2026 行业趋势)。
- **实现态(`interrupt=any_speech`)**:客户端本地 VAD 检测到持续语音 → 立即停 TTS 播放 + **200-300ms 最小时长门**滤咳嗽/单音节噪声(WS 传输下客户端管播放、本地停播,**全程不碰 LLM**)。室外 PTT 档无 barge-in。轮次/EoU 端点由 **FunASR runtime 服务端 fsmn-vad** 做(契约 `endpoint_silence_ms` 是适配层意图值,非引擎直通);**`is_speaking`** 是 runtime 唯一对得上的真字段(PTT 尾点)。
- **轮次纠错靠屏幕**:partial 上屏 + 一键取消/重说,比 LLM/模型判官便宜可靠(消费级纯语音才需把轮次判死=无别的纠错通道)。
- **预留升级(`interrupt=semantic`,🔧 缓做)**:真出现 VAD 误打断痛点再上 —— 轻量 turn-detector 模型(LiveKit/FireRedChat 中文,CPU)判附和 + `resume_false_interruption`(快停误判续接)+ OAC `post_end_monitor`(判停后监控防误切)。契约 schema 已留这些开关默认 off,升级=翻开关。
- **上下文截断**:被打断轮 v1 服务端粗截到"已发 message.delta"(OAC 更激进=不写 history/丢整轮);精确 audio_end_ms 截断级联无人做(OpenAI WS 特有),默认不做。

## 九、跨层契约 + 落地清单

**协议契约 = 唯一真相源在 `docs/app-realtime-protocol.md`(+ frontend-contract + runtime-logic)。本子系统实现它的媒体侧,不在此复述字段**(避免 drift)。媒体侧只需记住实现落点:`media_session.create/created`(单 WS、`transport=realtime_ws`、无 media_token)、上行 `track=audio_in` / 下行 `track=tts_audio` 二进制帧、`asr.partial/final`、`tts.started/completed/cancelled`、`media.commit/clear`——**字段定义一律以契约为准**。

**前端必改清单**(档位0,移动 standard-app + PC standardcloud 同模式):
- 接下行 tts_audio + 排期播放 + 弃本地 speechSynthesis(核心,后端早在发);

## 十、★架构师核查(已解 / 仍开 / 风险)

**已解**:
- 单/双 WS 之争 = 非问题(阿里 ISI/OpenAI 单 WS 同款;打断慢真因是客户端没清缓冲,非 TCP HoL;决定打断快慢 = 小帧+客户端管播放+干净指令,非连接数)。
- 打断真停进行中工具 = 已验(硬 task.cancel + 全链异步,无同步盲点)。
- TTS 容量 = 量化(≤2/卡),保护已具备(mineru 错峰)。
- 下行 pcm_stream = 后端已发,缺口纯在前端。

**仍开(需实测/拍板)**:
1. **室外声学默认档** —— 真实室外 A/B 定 NS/PTT/Paraformer-v2 组合;
2. **内置 AEC 能否消 Web Audio 播放** —— 逐端测,决定能否开真全双工(`echo_guard=false`);
3. **app 多实例外置** —— 现在只抽状态接口,数百并发要 HA 时落 Redis;
4. **6014 是否支持 keepalive** —— 决定 TTS 连接池化是否有效。

**风险**:
- ASR 句中重连丢音频(`ReconnectingAsrSession`)——移动现场弱网更常发;最低 = 断连即停录+提示重说,根治需上游可补帧(上游能力依赖)。
- 小程序 WebAudioContext 排期的基础库/iOS 一致性未真机验(影响小程序能否走 pcm_stream)。
- Paraformer-v2 在园区领域口音/术语下的实测 WER 未知(评估前不当定论)。
