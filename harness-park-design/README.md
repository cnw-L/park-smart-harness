## 一、Harness 是什么（一句话）

大模型只是一台"给文本、续写文本"的概率机——被动、无状态、不可靠、有限。**harness 是包在它外面的工程系统**，替它维护状态、驱动多步、把守边界、兜住意外，把"概率机"变成"能在真实环境完成多步任务、且行为受控的 agent"。

一句话压缩：**harness 一只手给出能动性，一只手扣住权威。**

---

## 二、那把刀：读 / 写权威之缝

harness 只有两类部件，劈开它们的是一条判据——**模型可读、但能否拥有写权威**：

| | 赋能层 | 治理层 |
|---|---|---|
| 为什么存在 | 让模型**能**把事做成 | 让模型行使能动性时**可问责、有边界** |
| 判据 | 模型终将自己又读又写 | 模型**可读、写权威必须外置** |
| 命运 | 随模型变强而**消失** | **不可侵蚀** |

设计纪律：**赋能层做薄、可删（注定被下一代模型作废）；治理层做厚、可证（唯一不会作废的投资）。** 每次有人喊"让模型自己管自己更高效"，都是在把写权威往模型手里塞——识别并守住这条缝，是 harness 工程唯一不能妥协的纪律。

## 三、本项目定位：服务任务 × 不可逆

- 园区 AI = **服务任务 × 不可逆**，对标 Claude Code 极（非 Hermes）。
- 域**不可沙箱**（真实设备控制不可逆、不可回滚）→ **治理工具 = 确认，不是围栏**。读/查可逆 → 可全自动；控/写不可逆 → **确认不可省**。
- harness = AI 服务的**管理/边界/编排层**，消费后端能力，**不持业务权威**（权限/事务/审计/真实执行归后端 = 数字底座）。
- 五层北极星：`C端入口 → AI对话中枢 → 子Agent能力层(MCP) → 数字底座`；**中枢 + 能力层是主战场**。

## 四、已收敛的设计要点（速览）

- **编排核**：一个递归 ReAct，显 = plan/todo、隐 = thought；plan 偏 Plan-and-Execute（稳定、按需修订）。
- **plan 写模型（地基，真实 harness 背书）**：plan = **全量快照 append 进 append-only 消息日志**（Claude Code 模式），文件 = 真相、可查询 DB = 可重建索引（Hermes `state.db` 损坏教训）。不建 plan AST、不做粒度事件溯源。
- **重规划**：触发 = plan 不再达成原目的（失败 or 执行后校验不过 or 用户 steer）；增量重规划 + 放弃/上报终止口。
- **上下文五层**（固定 / 记忆 / 知识 / 任务 / 历史）；**层序按变更频率排，服务缓存**——plan / 历史靠后，关键不变量每轮重注。
- **工具组织层（= 防腐层 = MCP 封装层）**：注册表（含输出契约 + 预算）+ 路由（分组地基 + 语义检索叠加）+ 分级 + 输出预算（读可截断、控不可静默截断）。
- **五道护栏关卡**（输入 / 意图 / 准备 / 执行 / 事实）：详见 [`harness护栏安全子系统设计说明.md`](harness护栏安全子系统设计说明.md)。早期文档中"三道闸"的提法已统一为五道关卡。
- **读/控分叉是贯穿全局的尺子**：安全、延迟、输出限额、对账策略都沿它分。
- **状态与持久化**：消息即状态；热状态 Redis + 冷状态 PostgreSQL（审计 append-only + 幂等键账本），详见 [`会话持久化子系统设计说明.md`](会话持久化子系统设计说明.md)。
- **记忆子系统**：语义 / 情景 / 偏好记忆，异步事件驱动写入，详见 [`memory-subsystem-design.md`](memory-subsystem-design.md)。
- **后端**：富 CRUD / SCADA，原料齐全；唯一真缺陷 = `deviceCtrl` 安全包络（无幂等 / 无回执）。控制安全靠**下发 → 读回 → 对账**，详见 [`devicectrl-接口改造建议.md`](devicectrl-接口改造建议.md)。

## 六、关键术语一致性约定

> 各分册若使用旧称谓，以本文档集最新约定为准。

| 约定术语 | 含义 | 旧称谓 / 注意 |
|---|---|---|
| **五道护栏关卡** | 输入 / 意图 / 准备 / 执行 / 事实，五层治理 | 早期称"三道闸"或"三道护栏"，已细化并统一为五道关卡 |
| **读 / 控分叉** | 可逆读操作可全自动；不可逆控制操作必确认 | read / control split |
| **消息即状态** | 会话状态 = append-only 消息日志 | state = message log |
| **B-path / C-path** | 会话边界审计的两种策略：B-path = 尽力写入；C-path = 写入失败则拒绝推进 | 见 [`会话持久化子系统设计说明.md`](会话持久化子系统设计说明.md) |
| **prepare / execute** | 控制类动作：prepare = 生成可确认提案；execute = 真实执行 | 控制闭环 |
| **deny-first / fail-safe** | 缺省不信任：无权限 / 异常 / 缺失一律拒绝 | 工具治理 v4 主轴 |
| **ContextAssembler 接缝** | 内圈循环委托给中圈组装上下文的协议接口 | `assemble(config, conversation) → list[Message]` |
| **ConversationStore 协议** | 内圈循环与会话持久化子系统的接缝 | 见 [`会话持久化子系统设计说明.md`](会话持久化子系统设计说明.md) |
| **长期记忆写入路径** | 由 `memory-subsystem-design.md` 定义的事件驱动异步写入 | 上下文管理子系统 v1 的"长期记忆预留空槽"仅指渲染侧 |

完整术语表与文档间联动规则见 [`术语表与文档联动约定.md`](术语表与文档联动约定.md)。
