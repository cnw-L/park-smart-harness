# 智慧园区 AI 服务设计方案

> 目标态（reference）架构，**基于项目北极星 + Harness 理论推导，不基于现有代码**。
> 理论依据见 [harness-research.md](harness-research.md)；本文是它在本项目的落地设计。

## 定位
- 园区 AI 服务 = **服务任务 × 不可逆**（对标 Claude Code 极，非 Hermes）。
- **治理工具 = 确认（非围栏）**——真实设备控制不可逆、不可沙箱、不可回滚。
- harness = **AI 服务的管理/边界/编排层**，消费后端能力来赋能，**不持业务权威**（权限/事务/审计/真实执行归后端 = 数字底座）。
- 北极星五层（腾讯总部园区 V6）：`C端入口 → AI对话中枢(意图/编排/降级) → 子Agent能力层(经MCP) → 数字底座(后端权威)`。**中枢 + 能力层是主战场。**
- 本期域：设备查询/控制 + 工单 + 知识；用户分层：员工(企微SSO+openid) / 市民(微信openid) + 数据鉴权。

## 一、总体架构（五层 × 赋能/治理两面）
```
C 端入口（前端，域外）
        │  自然语言
┌────────────────── AI 对话中枢（harness 本体）──────────────────┐
│ 会话层(消息即状态·持久化)                                       │ 治理
│  └ 递归 ReAct 控制循环（显=plan/todo 给人看，隐=思考驱动循环）  │ 赋能
│      意图 → 路由/plan 拆解 → 逐能力：                         │ 赋能
│        规划 → 落地(grounding) → ★执行前校验 → 行动闸 →          │ 赋/治
│        工具执行 → ★执行后校验 → 归一化 → 组装                   │ 赋能
│ 贯穿：上下文治理 · 工具治理 · 预算 · 审计trace · 五道护栏关卡（输入/意图/准备/执行/事实）       │ 治理
└────────────────────────────┬───────────────────────────────────┘
              MCP（统一注册/权限/日志；MCP 本身=治理对象）
┌────────────────── 子Agent 能力层（域=一个能力包）──────────────┐
│ 设备(查/汇总/消歧/控制工单) · 工单(查/报事报修) · 知识(RAG)     │
└────────────────────────────┬───────────────────────────────────┘
                    数字底座 / 后端（权威·真实执行·权限·事务·审计）
```

## 二、AI 对话中枢的模块（逐项标 赋能/治理·谁持笔）
| 模块 | 职责 | 层·持笔者 |
|---|---|---|
| 会话/状态 | 消息即状态、append-only、持久化、按 thread_id | 治理·append-only 外置 |
| 控制循环 | 驱动多轮、判停、人可随时介入 | 赋能 |
| 意图识别 | 知识/业务查询/动作准备/澄清/直答 分类 | 赋能 |
| 路由+编排 | 落到能力、拆**plan/todo 列表**(重试/重规划由 ReAct 循环动态处理,不用静态 DAG) | 赋能 |
| 上下文治理 | 分层组装(固定/记忆/知识/任务/历史)+压缩+预算 | 赋能(组装)，store 治理 |
| 规划 | 显 plan/todo + 隐 thought | 赋能 |
| 落地 grounding | NL→后端事实/参数、消歧(调后端解析) | 赋能·后端真相外置 |
| **★执行前校验** | grounded plan 能否执行（先验可验收=承诺点） | 治理·读规则 |
| 行动闸 | 读直放/控转 prepare/execute deny；确认按可逆性×影响分级 | 治理·权限外置 |
| 工具治理 | 注册+权限元数据+timeout/重试/失败降级+审计；控制类幂等 | 治理 |
| **★执行后校验** | 业务是否真满足、答案可否信 | 治理·读规则 |
| 归一化/组装 | 稳定结果 + 用户可读回答(可流式，事实护栏校验) | 赋能 |
| 预算 | 轮数/token/墙钟/工具次数上限；耗尽如实降级停报 | 治理·不可自扩 |
| 审计 trace | 每模块边界记事件，**模型不可写** | 治理 |
| 五道护栏关卡 | 输入(注入/紧急/信任边界)·意图(控制类高置信)·准备(参数合法)·执行(权限/可逆性/确认)·事实(执行类事实必须有 tool result 支撑) | 治理 |

**原则（理论 M5）**：治理模块对模型**只读**，写权威在后端/工程流程；赋能模块随模型变强收薄、做到可删。

## 三、能力层（MCP 封装 · 域无关契约）
- 能力 = **声明式 manifest**：`domain / task / risk(read|draft|ticket|execute|forbidden) / required_facts / grounding_policy / validation_policy / fallback_policy / allowed_tools / prompts`。
- 封成 **MCP tool + 统一注册/权限/日志**（对齐北极星 4.6）；**MCP 本身是治理对象**，注册/来源 deny-first，不当可信内部。
- 域：**设备**(status.query / status.summary / candidate.resolve / control_ticket.prepare) · **工单**(status.query / create.prepare) · **知识**(answer)。
- **域无关接口**（DomainGrounder/Validator/Gateway）→ "加一个域 = 填模板"。

## 四、核心治理纪律
1. **读/控分叉**：读可逆→全自动；控不可逆→ prepare→**前端确认**→后端执行(**幂等键**)；execute 永远 deny。
2. **确认按风险分级防确认疲劳**：仅不可逆/高影响弹确认；批量聚合；监测"秒确认"。
3. **两段校验**：执行前(承诺点)+执行后(业务核实)，治理读规则、模型不能改判。
4. **消息即状态 + 重放安全**：读能力可重放、控能力按幂等性分级，重放不重发已发指令。
5. **权限/记忆/预算/审计 = 只读旁路**：模型读不写；本期权限走后端"查权限"能力(不在中枢镜像一份)。
6. **谁持笔**：本项目=服务任务，笔交给**后端权威 + 工程流程**(契约测试/版本化)，非模型。

## 五、建设次序（治理优先 + 评测先行 + N=1→五层）
1. **评测基线**(N=1 读能力 device.status.query)+ **中枢骨架**(会话+控制循环+消息即状态)。
2. **读路径端到端**(意图→路由→落地→两段校验→组装)，真实/桩网关可切换。
3. **控制闭环**(prepare→确认→执行幂等)+ 五道护栏关卡 + 确认分级。
4. **上下文/工具/预算三层治理**(瓶颈本体)。
5. **多域解耦 + 工单域**；**MCP 封装**对齐五层。
6. **后端真实集成 + 流式 + 持久化会话**。

## 六、成功判据 + 边界
- **判据**(事务系统)：任务完成率、消歧准确率、**错误/越权动作率→0(红线)**、澄清精准度、理论 M6「不可写控制点占比」。
- **不做**：Hermes 式自学记忆(服务任务慎用)；长期个人记忆治理壳延后。
- **边界(评审已标)**：确认疲劳要分级；MCP 是新攻击面(本身要治理)；翻转命题配度量看。
