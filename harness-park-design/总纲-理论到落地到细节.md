# 智慧园区 AI 服务 · 总纲(理论 → 定位 → 架构 → 细节 → 建设)

> 这是整个资料夹的**单一主线**:从 harness 理论一路贯通到落地细节。

## 三条贯穿线(抽掉任一条,全盘散架)

1. **读/写权威之缝**:模型可读、但写权威必须外置。它劈开**赋能层**(随模型变强而消失)与**治理层**(不朽)。
2. **读/控分叉**:可逆→可全自动;不可逆→必确认。它贯穿安全、延迟、输出限额、对账策略——是落地全程的尺子。
3. **瘦引擎 + 子系统**:内圈循环只编排,治理/组装/校验/持久化全在接缝外。多次自审都在守这条。

# 第一部 · 理论(为什么 harness 是这形状)

详见 `harness-research.md`。提炼:

- **harness 是什么**:把"只会续写文本的概率机"(被动、无状态、不可靠、有限)转化为"能在真实环境完成多步、且受控"的 agent。**一手给能动性,一手扣权威。**
- **那把刀(读/写缝)**:赋能层=让模型**能**做成(循环/grounding/上下文/压缩),终将被模型自吸收;治理层=让模型**可问责有边界**(权限/审计/预算/append-only),**逻辑上不可被吸收**——被治理者无法治理自己。
- **翻转**:模型变强 → 赋能层薄、治理层重。投资策略:赋能做薄可删,治理做厚可证。
- **分野**:服务任务(记项目、单次可靠、自动护栏)vs 服务人(记用户、自我改进、人在回路)。
- **两个实证锚**:Claude Code(服务任务极)、Hermes(服务人极)——源码已 clone 到 `reference/hermes-agent/`。

---

# 第二部 · 定位(本项目站哪)

详见 `park-ai-service-design.md`。提炼:

- **坐标 = 服务任务 × 不可逆**,对标 Claude Code 极。
- **域不可沙箱(真实设备控制)→ 治理工具=确认,不是围栏**。读可逆→全自动;控不可逆→确认不可省。
- **harness = 管理/边界/编排层,不持业务权威**:权限/事务/审计/真实执行全归后端(数字底座)。
- **五层北极星**:`C端入口 → AI对话中枢 → 子Agent能力层(MCP) → 数字底座`。中枢+能力层是主战场。
- **成功判据**(事务系统非问答):任务完成率、消歧准确率、**错误/越权动作率→0(红线)**。

# 第三部 · 架构(三环 + 工具组织)

详见 `harness落地设计-讨论总结.md`。提炼:

**三环**(= 理论 M3 引擎/供给/保障):
- **内圈(引擎)**:递归 ReAct,**推进到退出原因**的步进函数(第四部)。
- **中圈(供给)**:上下文五层(固定/记忆/知识/任务/历史)· 记忆 · **工具组织层**。**上下文已收敛定稿见 `上下文管理子系统-设计.md`**(分层按功能标签非缓存;重注砍掉;存储热/冷分层;统一组装管线)。
- **外圈(保障)**:五道护栏关卡（输入/意图/准备/执行/事实，详见 `harness护栏安全子系统设计说明.md`） · 状态(消息即状态、append-only)· 审计 · 预算。

**工具组织层(= 防腐层 = MCP 封装层,别建三遍)**:
- 注册表(group/desc/input/**output+output_hint**/output_budget/risk/permission/norm)。
- 路由:**分组是地基,语义检索叠其上**(先定模块→模块内检索);每跳机制(语义预筛/循环 thought)按延迟×精度选。
- 分级:节点候选 ≤ ~7 才分;现 2 跳(L0 选域→L1 选工具);设备域=agent-as-tool,工单/知识扁平。
- 输出预算:top-k/投影/聚合摘要/截断;**读可截断、控不可静默截断**。

**编排范式**(M4):对外显式 plan/todo(可验收)、对内隐式 thought;plan 偏 Plan-and-Execute(稳定、按需修订)。
- **plan = 带 status 的 todo 列表,不是 DAG**(条件DAG 是腾讯 V6 需求,不采纳)。理由:DAG 是静态冻结图,而我们靠 ReAct 的**重试/重规划动态**——这些是循环动态、不是图的边。**并行=模型一轮多 tool_call 并发跑;串行=ReAct 天然顺序;重试=循环动态**,都不需要图。现有 `TopLevelPlan` 的 depends_on/activation_condition 不采纳,Phase 0/4 简化。
- **意图/路由**:不建重前置分类器(Claude/Hermes 都没有,路由就是模型 thought);仅快路留轻量语义预路由。**混合意图→拆多 todo(不是一个标签)**。**脏输入(ASR)不规则预清洗**——模型鲁棒;控制动作的错听由 grounding消歧+确认闸兜底。
- **能力 manifest 模板**:复用 `capability_platform` 现有 manifest + 补 `output_budget`/`permission`,`risk` 驱动闸;域无关靠 grounder/validator/gateway 三适配器——"**加一个域=填表+写三适配器**"。

# 第四部 · 内圈细节(定稿)

详见 `内圈循环-收敛定稿.md`(经 2 次独立评估 + Hermes 源码对照)。提炼:

**核心模型**:循环不是"跑到底",是**"在持久态上推进到某个退出原因"的步进函数**。
退出原因 = `completed / awaiting_confirmation(可恢复) / budget_exhausted / failed / interrupted`;恢复=用持久态再调一次(服务端每条 WS 消息本就调一次)。

**瘦引擎边界**:循环只 own —— while 推进 / 每轮 repair / 预算·grace·中断·深度 / 终止判定 / **携带不透明 pending 句柄挂起·恢复** / 消息合法性;其余 delegate 给五接缝(上下文·模型·工具执行·持久化·闸·verify)。

**三硬骨头**(均核过 Hermes 源码):
| 硬骨头 | 解 | 来源 |
|---|---|---|
| 恢复重建 | 每轮防御性 repair,不求精确 | 抄 Hermes `repair_message_sequence` |
| 挂起预算 | 迭代/token 计数,弃墙钟(挂起天然安全) | 抄 Hermes `IterationBudget` 纯计数 |
| 恢复幂等 | 不在循环里(见第五部) | 我们独有,Hermes 无 |

**有意背离 Hermes(都有理由)**:确认用挂起-恢复(它阻塞,因终端+可逆;我们服务端+不可逆)、统一 ask/allow/deny 闸(它分散)、共享预算池(它独立可超父)。

**事务化模型(独立设计+审查+Temporal/LangGraph对照后定稿,详见 `内圈循环-收敛定稿.md` §六·补)**:消息日志=事务机,**按迭代提交合法边界、中断=不提交(丢在途迭代)、挂起=提交 pending 边界、恢复=解析整批**。不变式"控制绝不内联"=事务回滚安全本身(可回滚迭代只能装幂等操作),做成 `is_control` 注册表类型、executor 拒绝内联。存储:Redis 热 / Postgres 审计+幂等键账本,不用 SQLite。**★ 硬依赖:后端 `deviceCtrl` 加 `commandId`+幂等前,不可逆控制不能上线**(持久执行救不了非幂等后端)。

**雏形(`src/agent_loop/`)已按事务化模型改造完成(2026-07-08 核码)**:`store.commit` 原子提交/按迭代边界、outcome 三态 + `PendingAction`、`is_control` 类型、删 deadline_s、`awaiting_confirmation` + 恢复解析整批、中断丢在途迭代、空文本重试、子 agent 错误分型 + 结构上不可执行控制、stall 守卫,均已落地(`loop.py`/`dispatch.py`/`budget.py`)。(原记“16+ 测试绿/待改造”为雏形期状态,已过时。)

# 第五部 · 治理细节(控制路径,从循环挪出)

详见 `harness落地设计-讨论总结.md` §4.5。提炼:

**闸 = ask/allow/deny,逐调用、执行前**:deny=无权限(靠"不进候选集"+后端数据过滤,借 Hermes block→合成→继续);allow=准入只读→自动;ask=准入不可逆→冻结挂起。

**权限两层**:① 工具可见性(无权限不进候选集);② 数据级(透传身份,**后端过滤数据**)。身份(员工企微SSO/市民微信openid)→ 后端查权限(缓存)∩ 工具 permission 元数据;harness 不镜像。

**ask 的冻结-挂起-恢复(P1,我们造)**:
- **复用 `control_ticket.prepare`**:工单 id 当幂等键,不另造。
- 恢复批准 → **直接执行冻结工单,绝不重问模型**(双重必要:幂等 + 残缺序列不能喂 provider)。
- 执行 = `deviceCtrl`(带幂等键)→ **读回 `getDevicePage` 对账** → outcome。
- 幂等真实承重面 = **非状态型动作**(纯状态型读回即兜底);**TOCTOU 对不可逆默认开**;in_flight 完整协议留后续。
- **批量确认**防确认疲劳(一轮多 ask 攒批一次列出)。

# 第六部 · 后端落地(防腐层 compose+cache)

详见 `后端接口情况与使用指南.md` + `devicectrl-接口改造建议.md`。提炼:

- **后端 = 富 CRUD/SCADA**(`业务平台.md`),原料齐全;harness 当防腐层 **compose + cache**,不直接消费裸后端。
- **三分表**:设备查/控、字典(`sycPointParamType` 的 isCtrl/枚举/范围)、权限——**①后端直接有**;解析/消歧/幂等去重——**②防腐层合成**;不可观测动作——**③降级给人**。
- **grounding 管线**:LLM 抽槽 → 规则解析(楼栋名→id、"空调"→pointType、过滤、消歧),模型不编 id。
- **下发→读回→对账**:控制天生两段,不信 deviceCtrl 的裸布尔,读回 status 对照字典。
- **缓存分层**:字典/区域树/权限狠缓存,实时态不缓存 → 多跳塌成 1 热读 + N 命中。
- **后端唯一真缺陷 = deviceCtrl 安全包络**(无幂等键/无回执):建议加 `requestId`+`commandId`+状态查询(`devicectrl-接口改造建议.md`,发后端用)。
