# 术语表与文档联动约定

> 本文档是 `harness-park-design/` 文档集的**一致性锚点**。  
> 所有分册使用以下术语时，含义必须与本表一致；若出现旧称谓，以本表为准。

---

## 一、全局核心概念

| 术语 | 定义 | 权威文档 |
|---|---|---|
| **harness** | 包在大模型外面的工程系统：维护状态、驱动多步、把守边界、兜住意外。 | [`harness-research.md`](harness-research.md) |
| **赋能层** | 让模型**能**把事做成（循环 / grounding / 上下文 / 压缩），随模型变强而变薄。 | [`harness-research.md`](harness-research.md) |
| **治理层** | 让模型行使能动性时**可问责、有边界**（权限 / 审计 / 预算 / append-only），不可被模型吸收。 | [`harness-research.md`](harness-research.md) |
| **读 / 写权威之缝** | 模型可读，但写权威必须外置。区分赋能与治理的根本判据。 | [`harness-research.md`](harness-research.md) |
| **服务任务 × 不可逆** | 本项目定位：单次任务正确性优先；真实设备控制不可逆、不可沙箱。 | [`park-ai-service-design.md`](park-ai-service-design.md) |
| **五层北极星** | `C端入口 → AI对话中枢 → 子Agent能力层(MCP) → 数字底座`。中枢 + 能力层是主战场。 | [`park-ai-service-design.md`](park-ai-service-design.md) |

## 二、护栏与关卡

| 术语 | 定义 | 权威文档 |
|---|---|---|
| **五道护栏关卡** | 输入 / 意图 / 准备 / 执行 / 事实，五层无状态治理层。 | [`harness护栏安全子系统设计说明.md`](harness护栏安全子系统设计说明.md) |
| **输入护栏** | 用户消息进入 `run_loop` 前：防注入、识别紧急词、标记不可信来源。 | [`harness护栏安全子系统设计说明.md`](harness护栏安全子系统设计说明.md) |
| **意图护栏** | 意图识别后：控制类意图必须高置信度，否则澄清。 | [`harness护栏安全子系统设计说明.md`](harness护栏安全子系统设计说明.md) |
| **准备护栏** | 模型输出 `prepare` 参数后：校验参数合法、无歧义、在静态权限范围内。 | [`harness护栏安全子系统设计说明.md`](harness护栏安全子系统设计说明.md) |
| **执行护栏** | 真实执行前：后端权限 / 状态校验、确认分级、幂等、批量冲突检查。 | [`harness护栏安全子系统设计说明.md`](harness护栏安全子系统设计说明.md) |
| **事实护栏** | 最终返回用户前：输出中的执行类事实必须有 tool result 支撑。 | [`harness护栏安全子系统设计说明.md`](harness护栏安全子系统设计说明.md) |
| **deny-first / fail-safe** | 缺省不信任：异常 / 超时 / 字段缺失 / 策略未命中一律按 `block` 处理。 | [`harness护栏安全子系统设计说明.md`](harness护栏安全子系统设计说明.md) |

**旧称谓统一**：早期文档中的"三道闸"、"三道护栏"、"输入 / 行动 / 输出三关"，均指上述五道关卡在演进前的粗粒度表述。后续引用时请使用"五道护栏关卡"，并在必要时说明：

- 原"输入关" → **输入护栏**
- 原"行动关" → **意图护栏 + 准备护栏 + 执行护栏**（行动前的双层校验 + 执行时校验）
- 原"输出关" / "事实关" → **事实护栏**

## 三、内圈循环

| 术语 | 定义 | 权威文档 |
|---|---|---|
| **消息即状态** | 会话状态 = append-only 消息日志；不另存状态机。 | [`内圈循环-收敛定稿.md`](内圈循环-收敛定稿.md) |
| **run_loop** | 在持久态上推进到某个退出原因的步进函数。 | [`内圈循环-收敛定稿.md`](内圈循环-收敛定稿.md) |
| **退出原因** | `completed / awaiting_confirmation / budget_exhausted / failed / interrupted`。 | [`内圈循环-收敛定稿.md`](内圈循环-收敛定稿.md) |
| **瘦引擎 + 接缝** | 循环只 own 推进 / 预算 / 中断 / 终止判定 / 消息合法性；其余委托给上下文 / 模型 / 工具执行 / 持久化 / 护栏 / verify 等接缝。 | [`内圈循环-收敛定稿.md`](内圈循环-收敛定稿.md) |
| **ContextAssembler 接缝** | `assemble(config, conversation) → list[Message]`，内圈委托给中圈组装上下文。 | [`context-assembly-design.md`](context-assembly-design.md) |
| **ConversationStore 协议** | 内圈委托给持久化子系统的存储接缝。 | [`会话持久化子系统设计说明.md`](会话持久化子系统设计说明.md) |
| **allow / ask / deny** | 工具执行前闸的三值裁决：`allow` 执行、`ask` 挂起待确认、`deny` 合成 blocked 结果。 | [`内圈循环-收敛定稿.md`](内圈循环-收敛定稿.md) |
| **PendingAction / pending 句柄** | 挂起时由闸/工具子系统生成的不透明句柄，循环只搬运、不解析。 | [`会话持久化子系统设计说明.md`](会话持久化子系统设计说明.md) |

## 四、持久化与状态

| 术语 | 定义 | 权威文档 |
|---|---|---|
| **热状态（Redis）** | 当前会话消息、当前边界、挂起状态；快速读写，带 TTL。 | [`会话持久化子系统设计说明.md`](会话持久化子系统设计说明.md) |
| **冷状态（PostgreSQL）** | 审计 append-only 日志 + 幂等键账本 + 长期归档；真相源。 | [`会话持久化子系统设计说明.md`](会话持久化子系统设计说明.md) |
| **B-path** | 边界审计的 best-effort 路径：Redis 提交后继续，PG 异步写入。 | [`会话持久化子系统设计说明.md`](会话持久化子系统设计说明.md) |
| **C-path** | 边界审计的 fail-closed 路径：PG 写入失败则拒绝推进。 | [`会话持久化子系统设计说明.md`](会话持久化子系统设计说明.md) |
| **idempotency_key / 幂等键** | 控制动作唯一标识，用于去重与崩溃恢复。 | [`devicectrl-接口改造建议.md`](devicectrl-接口改造建议.md) |
| **commandId / 指令回执** | 后端返回的指令编号，用于状态查询与审计。 | [`devicectrl-接口改造建议.md`](devicectrl-接口改造建议.md) |

## 五、上下文与记忆

| 术语 | 定义 | 权威文档 |
|---|---|---|
| **上下文五层** | 固定层 / 记忆层 / 知识层 / 任务层（plan）/ 历史层。 | [`上下文管理子系统-设计.md`](上下文管理子系统-设计.md) |
| **缓存序布局** | 稳的在前（缓存前缀：固定 + 记忆），变的在后（volatile：历史 + plan）。 | [`context-assembly-design.md`](context-assembly-design.md) |
| **记忆层（上下文）** | 当前用户身份口径（姓名 / 角色 / 部门），会话稳定，不建长期记忆写入。 | [`上下文管理子系统-设计.md`](上下文管理子系统-设计.md) |
| **长期记忆写入路径** | 语义 / 情景 / 偏好记忆的异步事件驱动写入，由 memory-subsystem 定义。 | [`memory-subsystem-design.md`](memory-subsystem-design.md) |
| **MemoryEngine** | 记忆读取 / 写入 / 召回的统一入口。 | [`memory-subsystem-design.md`](memory-subsystem-design.md) |
| **StreamingContextScrubber** | 流式输出中的记忆上下文清洗器，防止召回内容污染生成。 | [`memory-subsystem-design.md`](memory-subsystem-design.md) |
| **`<memory-context>` fence** | 召回记忆在 prompt 中的边界框，标注"非用户输入 · 当背景"。 | [`memory-subsystem-design.md`](memory-subsystem-design.md) |

**注意**：[`上下文管理子系统-设计.md`](上下文管理子系统-设计.md) 中"长期记忆：预留空槽，v1 不建写入路径"仅指**上下文渲染侧**；长期记忆的写入、存储、召回由 [`memory-subsystem-design.md`](memory-subsystem-design.md) 专门定义。

## 六、工具与后端

| 术语 | 定义 | 权威文档 |
|---|---|---|

## 七、文档间引用规范

1. **权威来源唯一**：同一概念只在最专门的文档中详细定义，其他文档引用而非重定义。
2. **相互链接**：每份文档顶部应声明"参见"与"被参见"；新增文档必须先入 README 索引和本术语表。
3. **版本独立**：本文档集版本为 `v1.0`，各分册保留自身版本号；若分册内容与本文档集版本冲突，以本文档集术语表和最新分册为准。
4. **术语优先**：当分册使用"三道闸"等旧称谓时，读者应自动映射到本表最新术语；后续编辑应逐步替换旧称谓。

## 八、快速对照：旧称谓 → 新术语

| 旧称谓 | 新术语 | 说明 |

| 持久化（内圈循环旧称） | ConversationStore 协议 + 会话持久化子系统 | 详见 [`会话持久化子系统设计说明.md`](会话持久化子系统设计说明.md) |
