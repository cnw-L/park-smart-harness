# 内圈循环 · 真实持久化部件实施计划(P1–P4)

> 目标:把内圈仍是桩的持久化 I/O 换成真实部件——按 `内圈循环-收敛定稿.md` §六补 存储分层:**Redis 热会话+当前边界(挂起加 TTL)/ Postgres 审计 append-only + 幂等键账本(unique)**,不用 SQLite。
> 底座事实(部署不变,见 env):Redis `redis://192.168.1.90:6379/0`(`ASSISTANT_REDIS_URL`,TTL 旋钮 `ASSISTANT_REDIS_CHECKPOINT_TTL_MINUTES`/`_REFRESH_ON_READ`);Postgres `postgresql://postgres:<pwd>@192.168.1.90:5432/smart_park`(`SPA_STORAGE__POSTGRES_DSN`,密码见部署侧 env)。
> 库:`redis.asyncio`、`asyncpg`(均已装,异步,契合 async loop)。无 fakeredis/pytest_asyncio → **离线单测覆盖纯逻辑(codec),真实后端用 live 集成测试**,默认 skip(`AGENT_LOOP_LIVE_INFRA=1` 打开;两台 90 服务本机可达)。
> **新代码适应新底座**:只参考"怎么连 90 上的 redis/pg",不复用旧代码结构(现有代码也没有裸 redis/pg 客户端可镜像)。
> 纪律:实现 `ConversationStore` 协议(load/commit/latest_boundary/resolve_pending),与 `InMemoryConversationStore` **同契约**;InMemory 保留给离线单测。
> 工作方式:subagent-driven(implementer + spec核查 + 质量核查)。分支 `feat/agent-loop-inner-ring`;`git add` 只加自己文件。

## P1 — 序列化 codec(地基,纯逻辑离线可测)
**Files**:新 `src/agent_loop/codec.py`;Test `tests/test_agent_loop_codec.py`。
- `Message`/`ToolCallReq`/`Boundary`/`PendingAction` ↔ JSON-safe `dict` 双向编解码:`encode_message/decode_message`、`encode_boundary/decode_boundary`(boundary.pending_batch 内含 PendingAction → 递归编解码;budget_snapshot 是 dict 原样)。
- round-trip 保真:含 tool_calls 的 assistant、tool 消息(tool_call_id/name/is_error)、awaiting_confirmation 边界(pending_batch 非空)、空 pending_batch、budget_snapshot。
- 防御:未知字段忽略、缺字段用默认。纯函数,无 I/O。
- **Test**:每种消息/边界 encode→json.dumps→json.loads→decode 等价;PendingAction(frozen_action dict + handle)round-trip。

## P2 — RedisConversationStore(热会话,§六补 Redis 层)
**Files**:新 `src/agent_loop/redis_store.py`;Test `tests/test_agent_loop_redis_store.py`(live,gated)。
- `RedisConversationStore(ConversationStore)`,`redis.asyncio.Redis.from_url(ASSISTANT_REDIS_URL)`;key 前缀 `agentloop:{thread_id}:messages`(list)/`:boundaries`(list)。
- `commit(thread_id, new_messages, boundary)`:**原子**(`pipeline(transaction=True)`/MULTI)—— RPUSH 编码后的 new_messages + RPUSH 编码 boundary,一次提交;边界=`awaiting_confirmation` 时给该 thread 的 key 设 TTL(`ASSISTANT_REDIS_CHECKPOINT_TTL_MINUTES`,未配则不设),正常迭代刷新/续期(REFRESH_ON_READ)。
- `load(thread_id)`:读 messages + boundaries;**尾部丢到最后一个 boundary**(与 InMemory 同语义:committed 只到最后边界);返回 `Conversation`。
- `latest_boundary(thread_id)`:取 boundaries 最后一条解码;空→None。
- `resolve_pending(thread_id, resolved, boundary)`:原地替换 committed messages 中匹配 tool_call_id 的占位(读出→改→写回,事务内)+ RPUSH 新 boundary。注:生产审计 append resolution-event 在 P3 PG,此处热态原地换可。
- 连接/池:惰性连接;`aclose()` 清理。配置从 env 读(P4 的 settings,或本任务内联读 `os.getenv`)。
- **Test(live,`@skipif AGENT_LOOP_LIVE_INFRA!=1`)**:commit 两迭代→load 全;撕裂(只 push messages 无 boundary)→load 丢到上一边界;latest_boundary;resolve_pending 换占位;awaiting_confirmation 设了 TTL(`ttl(key)>0`)。用随机 thread_id 前缀避免污染,测后清理 key。

## P3 — Postgres 幂等账本 + 审计(§六补 Postgres 层)
**Files**:新 `src/agent_loop/pg_store.py`;Test `tests/test_agent_loop_pg_store.py`(live,gated)。
- `asyncpg` 连接(`SPA_STORAGE__POSTGRES_DSN`);启动 `CREATE TABLE IF NOT EXISTS`(自举,幂等 DDL):
  - `agentloop_idem(idem_key text primary key, status text, result_json jsonb, created_at timestamptz default now())` —— unique 让重复 resolve 变 no-op。
  - `agentloop_audit(id bigserial primary key, thread_id text, seq int, boundary_status text, payload jsonb, created_at timestamptz default now())` —— append-only。
- `PgIdempotencyLedger`:`async get(idem_key)->result|None`、`async put_if_absent(idem_key, status, result)->bool`(`INSERT ... ON CONFLICT DO NOTHING` 返回是否首次)。
- `PgControlCapability(ControlCapability)`:`freeze(call)` 铸 idem_key(uuid)+冻结 args(同 Fake);`async resolve(pending, decision)`:approve → 账本 `get` 命中则返缓存(不重发);否则**执行(此处仍桩 echo,因真 deviceCtrl 幂等是上线硬依赖,未接)**+ `put_if_absent` 入账 + 返结果;reject → 返拒绝、不入账。与 FakeControlCapability 同语义,只把 ledger 换成 PG unique。
- `audit_boundary(thread_id, boundary)`:INSERT 一行(payload=编码 boundary)。供 store/loop 在 commit 时调(本任务先提供函数 + live 测,接线在 P4/后续)。
- **Test(live,gated)**:`put_if_absent` 同 idem_key 第二次返 False、结果不变(幂等);`PgControlCapability` approve 两次同 pending → execute 一次(用账本计数证);reject 不入账;audit 能写读。测后清理(用随机前缀 idem_key/thread_id)。
- **★ 标注**:真不可逆控制上线仍**硬依赖**后端 deviceCtrl 加 commandId+幂等;本任务把 harness 侧幂等账本做成真 PG,但"执行 deviceCtrl"那一步仍桩。

## P4 — 配置模块 + 真实部件端到端 smoke
**Files**:新 `src/agent_loop/settings.py`(读 env:redis url/ttl、pg dsn、llm,集中);Test `tests/test_agent_loop_infra_smoke.py`(live,gated)。
- `settings.py`:`load_infra_settings()` 从 env 读 `ASSISTANT_REDIS_URL`/`ASSISTANT_REDIS_CHECKPOINT_TTL_MINUTES`/`ASSISTANT_REDIS_CHECKPOINT_REFRESH_ON_READ`/`SPA_STORAGE__POSTGRES_DSN`/`ASSISTANT_LLM_*`,带默认(90 那套)。纯读取 + 默认,离线可单测(不连)。
- **端到端 live smoke(gated)**:`run_loop(OpenAIModelCaller + RedisConversationStore)` 跑**一整轮真机**——给真 echo 工具,qwen 真决定调它、引擎执行、真提交进 Redis、续到 completed;再 `RedisConversationStore.load` 重载验证持久化。这是"内圈在**真模型 + 真存储**下端到端成不成立"的硬考。
- **Test**:settings 离线单测(env→值);infra smoke gated。
